## 1. Motivation: asking, matching, and reading are different jobs

A query describes what information is currently useful. A key describes how a memory record should be matched. A value contains information that can be passed to the output.

In a library analogy, a question, a catalog entry, and the book contents play different roles. In a neural network, they are numerical vectors learned through the task loss. They need not correspond to human-readable categories.

## 2. One query and several records

Let $\mathbf{q}\in\mathbb{R}^{d_k}$ be one query. Each memory item has a key $\mathbf{k}_j\in\mathbb{R}^{d_k}$ and a value $\mathbf{v}_j\in\mathbb{R}^{d_v}$.

An inner product gives a simple score:

$$
s_j=\mathbf{q}^{\mathsf T}\mathbf{k}_j.
$$

Query and key dimensions must match because the score sums coordinate products. Value dimension $d_v$ may differ because it is used in the later weighted read:

$$
\alpha_j=\operatorname{softmax}(\mathbf{s})_j,
\qquad
\mathbf{o}=\sum_j\alpha_j\mathbf{v}_j.
$$

This section uses unscaled scores to isolate the roles. Section 07.3 introduces the standard $1/\sqrt{d_k}$ factor and derives its motivation.

## 3. Learned projections let matching adapt to the task

Suppose a query source vector is $\mathbf{x}\in\mathbb{R}^{D_q}$ and a memory vector is $\mathbf{m}_j\in\mathbb{R}^{D_m}$. Using column-vector notation,

$$
\begin{aligned}
\mathbf{q}&=\mathbf{W}_Q\mathbf{x},
&\mathbf{W}_Q&\in\mathbb{R}^{d_k\times D_q},\\
\mathbf{k}_j&=\mathbf{W}_K\mathbf{m}_j,
&\mathbf{W}_K&\in\mathbb{R}^{d_k\times D_m},\\
\mathbf{v}_j&=\mathbf{W}_V\mathbf{m}_j,
&\mathbf{W}_V&\in\mathbb{R}^{d_v\times D_m}.
\end{aligned}
$$

Biases are omitted here for clarity; implementations may include them.

These are ordinary linear layers from Part I. The new operation is using their outputs to determine a data-dependent mixture.

If $Q$ and $K$ used the same raw vector representation without separate projections, matching and content requirements would be more constrained. Separate projections allow different roles, though particular architectures may tie parameters deliberately.

### A complete two-record read

Take $\mathbf{q}=(1,0)^{\mathsf T}$, keys $\mathbf{k}_1=(\log 3,1)^{\mathsf T}$ and $\mathbf{k}_2=(0,2)^{\mathsf T}$, and values $\mathbf{v}_1=(2,4)^{\mathsf T}$ and $\mathbf{v}_2=(8,0)^{\mathsf T}$.

First match: the scores are $\log 3$ and 0. Then normalize: the weights are $3/4$ and $1/4$. Finally read:

$$
\mathbf{o}
=\frac34\begin{bmatrix}2\\4\end{bmatrix}
+\frac14\begin{bmatrix}8\\0\end{bmatrix}
=\begin{bmatrix}3.5\\3\end{bmatrix}.
$$

The second key coordinate did not affect this particular query, but the second **value** coordinate still contributes to the output. That is why matching space and returned-content space should not be confused.

### Why learn Q and K instead of comparing raw inputs?

Substitute the projections into the score:

$$
s_j=(\mathbf{W}_Q\mathbf{x})^{\mathsf T}
     (\mathbf{W}_K\mathbf{m}_j)
=\mathbf{x}^{\mathsf T}
 \underbrace{\mathbf{W}_Q^{\mathsf T}\mathbf{W}_K}_{(D_q,D_m)}
 \mathbf{m}_j.
$$

The middle matrix learns which input features should interact across the two sources. The scalar score is not generally a cosine similarity: vector lengths matter, and Q/K are not automatically normalized.

## 4. Several queries give a matrix of reads

Put $T_q$ queries into rows of $\mathbf{Q}\in\mathbb{R}^{T_q\times d_k}$, and $T_k$ memory keys into rows of $\mathbf{K}\in\mathbb{R}^{T_k\times d_k}$.

Then $\mathbf{Q}\mathbf{K}^{\mathsf T}$ has shape $(T_q,T_k)$. Row $i$ lists the scores of query $i$ against every key. Normalize each row, because each query needs its own distribution over memory.

Values form $\mathbf{V}\in\mathbb{R}^{T_k\times d_v}$. The readout has shape $(T_q,d_v)$. Keys and values must share the **memory-length** axis, not necessarily their feature dimension.

## 5. Self-attention and cross-attention describe sources

In self-attention, the query, key, and value projections take their source from the same sequence $\mathbf{X}$. Their numerical vectors generally differ because the projection matrices differ.

In cross-attention, queries come from one sequence and keys/values from another. For example, a decoder can query encoder outputs. The two sequence lengths may differ.

The term “self” does not mean each token can only attend to itself. It means the collection being queried is the same source collection.

Nor is self-attention generally symmetric. With different query/key projections, $s_{ij}$ need not equal $s_{ji}$; row normalization can also break symmetry of weights.

## 6. Why the projections can learn

The loss depends on the weighted read. Changing a value directly changes the information read. Changing a key or query changes the scores, then the weights, then the read.

All these operations are differentiable away from separately imposed discontinuities such as hard selection. Section 07.3 derives the derivatives of the read and the score normalization. There is no need to assign semantic labels to Q/K/V for backpropagation to train them.

## 7. Runnable experiment: cross-attention with unequal dimensions

```python
import math
import torch
from torch import nn

torch.manual_seed(22)
B, Tq, Tk, Dq, Dm, dk, dv = 2, 3, 5, 4, 6, 3, 2
query_source = torch.randn(B, Tq, Dq, dtype=torch.float64)
memory = torch.randn(B, Tk, Dm, dtype=torch.float64)
q_proj = nn.Linear(Dq, dk, bias=False).double()
k_proj = nn.Linear(Dm, dk, bias=False).double()
v_proj = nn.Linear(Dm, dv, bias=False).double()

Q, K, V = q_proj(query_source), k_proj(memory), v_proj(memory)
scores = Q @ K.transpose(-2, -1)
weights = scores.softmax(dim=-1)
output = weights @ V
assert scores.shape == (B, Tq, Tk)
assert output.shape == (B, Tq, dv)
torch.testing.assert_close(weights.sum(-1), torch.ones(B, Tq, dtype=torch.float64))

# Holding Q and K fixed keeps weights fixed, even if values change.
changed_values = V + 2.0
torch.testing.assert_close(weights @ changed_values, output + 2.0)

target = torch.randn_like(output)
loss = (output - target).square().mean()
loss.backward()
for name, layer in [("Q", q_proj), ("K", k_proj), ("V", v_proj)]:
    assert layer.weight.grad is not None
    assert torch.isfinite(layer.weight.grad).all()
    print(name, "weight / gradient norm:", layer.weight.shape, layer.weight.grad.norm().item())

# Deliberately compare a query's memory distribution with another query's.
print("first query weights:", weights.detach()[0, 0])
print("second query weights:", weights.detach()[0, 1])
```

The gradient test checks connection to the loss, not whether these randomly initialized projections already perform useful retrieval.

## 8. Mistakes to catch with axis names

`K.transpose(-2, -1)` swaps the last two axes; `K.T` on a batched tensor does not mean “transpose each matrix” and can reverse more axes than intended.

A softmax over the query axis makes each **key** compete across queries. That is a different operation from each query choosing among keys.

The values' last dimension determines readout width. It need not equal the number of keys or the original model width.
