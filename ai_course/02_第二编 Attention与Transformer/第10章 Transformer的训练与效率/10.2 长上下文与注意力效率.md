# 10.2 KV Caching and Efficient Attention

第二编目录 · 本章导读

> Prerequisites: causal Transformer implementation and position indices. Goal: derive correct incremental decoding, including chunked-cache masks, and distinguish caching from other efficiency methods.

## 1. Motivation: generation repeats work on the prefix

The simple generator in 09.4 runs the entire prefix again for every new token. In a causal model, an earlier position cannot see later tokens. Its representation at a fixed layer is therefore unchanged when a later token is appended, provided parameters, positions, masks, and evaluation behavior remain consistent.

This suggests storing some earlier results. At each layer, future queries need previous **keys and values**. Store them in a layer-local KV cache instead of recomputing the whole earlier prefix.

No new training is needed to establish this computational reuse. Numerical outputs should match the uncached causal model up to floating-point differences.

## 2. Prefill and decode are different workloads

**Prefill** processes the observed prompt, often many tokens in parallel, and fills every layer's cache.

**Decode** processes one or a small number of new tokens. Each new query attends to cached earlier keys/values plus permitted new ones.

Queries from old positions are not needed for future readouts, so an ordinary KV cache does not retain them. Each layer has its own projections and hidden states, so sharing one cache across all layers would be wrong.

This cache is request-specific model state, not long-term semantic memory and not a guarantee the model recalls arbitrary earlier facts correctly.

Why can cached keys/values be reused at **every** layer? At layer 0, old token and position embeddings do not change when a token is appended. If old inputs to layer $\ell$ are unchanged, its causal attention never reads the appended future token, and its position-wise norm/FFN sees the same features. Its old outputs are therefore unchanged too. This induction fails for bidirectional attention, where appending a token can change earlier outputs.

## 3. Derive the cache update

Suppose a layer has cached $P$ positions and receives a new chunk of $C$ positions. New projections have shape $(B,h,C,d_h)$; old cached keys/values have shape $(B,h,P,d_h)$.

Concatenate along the sequence axis:

$$
\mathbf{K}_{\mathrm{all}}=
[\mathbf{K}_{\mathrm{past}};\mathbf{K}_{\mathrm{new}}],
\quad
\mathbf{V}_{\mathrm{all}}=
[\mathbf{V}_{\mathrm{past}};\mathbf{V}_{\mathrm{new}}].
$$

New queries produce scores of shape $(B,h,C,P+C)$. Old outputs do not need to be recalculated.

The same reasoning applies layer by layer: earlier representations are unchanged by causality, and the new layer input comes from the newly processed positions in the previous layer.

## 4. The rectangular causal mask has an offset

Local query index $i\in\{0,\ldots,C-1\}$ corresponds to absolute position $P+i$. A key index $j$ is allowed when

$$
j\leq P+i.
$$

For $P=3,C=2$, the first new query may read keys 0–3 and the second may read 0–4:

$$
\mathbf{M}=\begin{bmatrix}1&1&1&1&0\\1&1&1&1&1\end{bmatrix}.
$$

A naive $2\times5$ lower triangle would allow only one key in the first row and two in the second, blocking valid cached history.

A square lower triangle sliced without the offset may be wrong. In PyTorch SDPA, the documented non-square `is_causal=True` alignment is upper-left; blindly using it for a one-token query against a long cache can allow only the first key rather than the whole prefix.

Use an explicit offset-aware allowed mask with `is_causal=False` for this teaching implementation. Check the API and any specialized causal-bias helper you choose in production.

中文提示：有 cache 时，query 的第 0 行不再代表整段序列的位置 0。mask 和位置编码都要加上已经缓存的长度。

## 5. Position and cache validity rules

For learned absolute embeddings, a new chunk uses positions $P,\ldots,P+C-1$. For common RoPE implementations, cache keys rotated at their original positions and rotate only new queries/keys at the new positions.

Cache reuse assumes the same parameters and prefix. After an optimizer update, a changed prompt, different batch ordering, or incompatible device/dtype settings, old cache contents are generally invalid. Reset or update them deliberately.

The example is inference-only, fixed batch size, unpadded, and uses a uniform model dtype without autocast. It validates both K and V tensors in every layer: rank, batch, heads, per-head width, prefix length, device, and dtype. A same-shaped cache from the wrong request or older model weights cannot be recognized from these tensors alone; the caller must reset it. A production wrapper should track request/prefix and model-version metadata.

Padding, per-example lengths, beam reordering, cache eviction, and sliding windows need additional bookkeeping. Dropping old entries is an approximation unless the architecture's attention window already excludes them.

## 6. Runnable implementation: cached decoding with the model from 09.4

The companion directory contains `transformer_core.py` with the exact model defined in 09.4. Run this example via its companion script so the import resolves, or place it alongside that module.

```python
import torch
import torch.nn.functional as F

@torch.no_grad()
def cached_forward(model, ids, caches=None):
    if any(module.training for module in model.modules()):
        raise ValueError("cached_forward requires every module in evaluation mode")
    if ids.ndim != 2 or ids.shape[0] == 0 or ids.shape[1] == 0:
        raise ValueError("provide a nonempty batch of token IDs")
    if ids.dtype not in (torch.int32, torch.int64):
        raise ValueError("token IDs must be integers")
    if ids.device != model.token.weight.device:
        raise ValueError("token IDs and model must be on the same device")
    if len(model.blocks) == 0:
        raise ValueError("this cache representation requires at least one block")
    B, C = ids.shape

    if caches is None:
        caches = [None] * len(model.blocks)
        P = 0
    else:
        if not isinstance(caches, (list, tuple)) or len(caches) != len(model.blocks):
            raise ValueError("provide one complete KV pair per layer")
        P = None
        for block, pair in zip(model.blocks, caches):
            if not isinstance(pair, (tuple, list)) or len(pair) != 2:
                raise ValueError("each layer cache must be a (K, V) pair")
            Kpast, Vpast = pair
            if not all(isinstance(t, torch.Tensor) and t.ndim == 4 for t in pair):
                raise ValueError("cached tensors must have shape (B, heads, P, d)")
            if P is None:
                P = Kpast.shape[-2]
            expected = (B, block.attn.heads, P, block.attn.head_dim)
            if tuple(Kpast.shape) != expected or tuple(Vpast.shape) != expected:
                raise ValueError("cache batch, heads, prefix lengths, or widths disagree")
            weight = block.attn.qkv.weight
            if any(t.device != weight.device or t.dtype != weight.dtype for t in pair):
                raise ValueError("cache device/dtype must match its projection weights")
    if P + C > model.max_length:
        raise ValueError("position range exceeded")

    positions = torch.arange(P, P + C, device=ids.device)
    x = model.token(ids) + model.position(positions)[None]
    new_caches = []
    for block, previous in zip(model.blocks, caches):
        z = block.norm1(x)
        Q, K, V = block.attn.qkv(z).chunk(3, dim=-1)
        h, d = block.attn.heads, block.attn.head_dim
        def split(tensor):
            return tensor.reshape(B, C, h, d).transpose(1, 2)
        Q, K, V = split(Q), split(K), split(V)
        if previous is not None:
            K = torch.cat([previous[0], K], dim=-2)
            V = torch.cat([previous[1], V], dim=-2)
        query_positions = torch.arange(P, P + C, device=ids.device)
        key_positions = torch.arange(P + C, device=ids.device)
        allowed = key_positions[None, :] <= query_positions[:, None]
        read = F.scaled_dot_product_attention(Q, K, V, attn_mask=allowed,
                                             dropout_p=0.0, is_causal=False)
        x = x + block.attn.out(read.transpose(1, 2).reshape(B, C, -1))
        x = x + block.ffn(block.norm2(x))
        new_caches.append((K, V))
    return model.head(model.final_norm(x)), new_caches

from transformer_core import TinyTransformer

torch.manual_seed(34)
torch.set_num_threads(1)
model = TinyTransformer(max_length=20).double().eval()
tokens = torch.randint(1, 9, (2, 8))
with torch.no_grad():
    full = model(tokens)
cache, outputs, offset = None, [], 0
for chunk_length in [3, 1, 4]:
    chunk = tokens[:, offset:offset+chunk_length]
    logits, cache = cached_forward(model, chunk, cache)
    outputs.append(logits)
    offset += chunk_length
streamed = torch.cat(outputs, dim=1)
torch.testing.assert_close(streamed, full, atol=1e-9, rtol=1e-7)

prompt = tokens[:, :4]
uncached = model.generate(prompt, new_tokens=4)
prefix_logits, cache = cached_forward(model, prompt)
generated = prompt.clone()
for step in range(4):
    next_id = prefix_logits[:, -1].argmax(-1, keepdim=True)
    generated = torch.cat([generated, next_id], dim=1)
    if step < 3:
        prefix_logits, cache = cached_forward(model, next_id, cache)
torch.testing.assert_close(generated, uncached)
print("chunked logits maximum difference:", (streamed - full).abs().max().item())
print("cached and uncached generation match")
```

The companion script additionally compares one-token chunks, a single full chunk, and equal two-token chunks. It deliberately passes an incomplete layer list, invalid K/V shapes (including the value batch axis), inconsistent prefix lengths, wrong dtype, excessive context, and training mode, and requires clear errors.

The model here is random because numerical equivalence does not require trained weights. It does not demonstrate learned copying; that is tested in 09.4.

Repeated `torch.cat` copies cache storage and is convenient for teaching, not an optimal allocation strategy. A production implementation may preallocate or page cache memory.

## 7. Derive memory growth

For $L$ layers, batch size $B$, length $T$, $h_{\mathrm{kv}}$ key/value heads, per-head dimension $d_h$, and $b$ bytes per element, KV cache size is approximately

$$
M_{\mathrm{KV}}=2LBT h_{\mathrm{kv}}d_h b.
$$

The factor 2 is for keys and values. Ordinary MHA has $h_{\mathrm{kv}}=h$, so $h d_h=D$.

Grouped-query attention uses fewer KV heads than query heads; multi-query attention uses one KV head. These change the model's projection/sharing design. They are not obtained by arbitrarily discarding cache heads of an already trained MHA checkpoint.

## 8. Caching changes repeated work, not all quadratic costs

An uncached generator repeatedly computes full-prefix attention; summing squared prefix lengths over a long generation can give cubic total score/read work in the final length.

With a cache, each new token attends to a growing prefix, so the total decode score/read work across generated tokens is roughly quadratic in generated length, plus prompt contributions. Per-token attention still grows with prefix length.

For an initial prompt length $P$ and $N$ generated tokens, the simple generator processes prefix lengths $P,P+1,\ldots,P+N-1$. Its score/read work is proportional to $\sum_{t=0}^{N-1}(P+t)^2D$. A cached generator performs one prefill proportional to $P^2D$, then $N-1$ one-query reads proportional to

$$
D\sum_{t=1}^{N-1}(P+t)
=D\left((N-1)P+\frac{N(N-1)}2\right).
$$

This counts attention score/read operations only; projections, FFNs, the vocabulary head, and cache memory traffic add other costs. The last generated token need not be fed back when no next prediction is requested.

Prefill remains a long-sequence attention problem. KV caching is mainly an inference reuse method; teacher-forced training normally processes all positions together and needs gradients through the whole training computation.

## 9. Distinguish efficient attention approaches

| Method | What changes | Main qualification |
|---|---|---|
| KV caching | Reuses earlier inference projections | Keeps a growing request-specific cache |
| FlashAttention-style kernels | Tiled exact attention with online normalization and less memory traffic | Same dense rule up to numerical details; hardware/kernel dependent |
| Sliding-window/sparse attention | Restricts allowed query–key connections | Changes connectivity and possibly model behavior |
| Kernel/linear attention | Rewrites or approximates similarity/normalization | Generally not exactly ordinary softmax attention |
| GQA/MQA | Shares keys/values across query heads | Architecture and training/checkpoint design change |

An explicit dense causal mask alone is not a sparse kernel. A “linear attention” formula should not be described as an exact algebraic reordering of ordinary exponential softmax unless its assumptions actually establish that.

## 10. Derive an exact blockwise softmax read

Why can a tiled implementation avoid retaining all probabilities? For one query, the desired output can be written as a ratio:

$$
\mathbf{o}=\frac{\sum_j \exp(s_j)\mathbf{v}_j}{\sum_j\exp(s_j)}.
$$

Maintain three running quantities over processed keys: maximum score $m$, normalized denominator $\ell=\sum_j\exp(s_j-m)$, and vector numerator $\mathbf{z}=\sum_j\exp(s_j-m)\mathbf{v}_j$.

When a new block of scores $\{s_j:j\in\mathcal B\}$ arrives, set $m'=\max(m,\max_{j\in\mathcal B}s_j)$. Old accumulated terms were measured relative to $m$, so rescale them by $a=\exp(m-m')$:

$$
\begin{aligned}
\ell'&=a\ell+\sum_{j\in\mathcal B}\exp(s_j-m'),\\
\mathbf{z}'&=a\mathbf{z}
+\sum_{j\in\mathcal B}\exp(s_j-m')\mathbf{v}_j.
\end{aligned}
$$

To derive the rescaling, take any old term $\exp(s_j-m)$. Relative to the new maximum it must become $\exp(s_j-m')=\exp(s_j-m)\exp(m-m')$. Every old numerator and denominator term receives the same factor, so their ratio is preserved.

For a two-key scalar read with scores $[0,\log 3]$ and values $[2,8]$, processing the first key gives $m=0,\ell=1,z=2$. The second key changes the maximum to $\log3$, so $a=1/3$. The updates give $\ell'=1/3+1=4/3$ and $z'=2/3+8=26/3$, hence $o=z'/\ell'=6.5$, the same as dense weights $[1/4,3/4]$.

After all blocks, return $\mathbf{z}/\ell$. The maximum rescaling avoids overflow while preserving the ratio. We need not store all probability entries at once.

This illustrates an important idea behind exact tiled attention. It is not a complete FlashAttention kernel: efficient hardware tiling, data movement, parallelization, and backward recomputation are additional engineering work. The dense query–key interactions still exist.

```python
import torch

torch.manual_seed(36)
scores = 1000 + torch.randn(17, dtype=torch.float64)
values = torch.randn(17, 5, dtype=torch.float64)
running_max = torch.tensor(-torch.inf, dtype=torch.float64)
denominator = torch.tensor(0.0, dtype=torch.float64)
numerator = torch.zeros(5, dtype=torch.float64)

for start in range(0, len(scores), 4):
    block = scores[start:start+4]
    block_values = values[start:start+4]
    new_max = torch.maximum(running_max, block.max())
    old_scale = (running_max - new_max).exp()
    exponentials = (block - new_max).exp()
    denominator = old_scale * denominator + exponentials.sum()
    numerator = old_scale * numerator + exponentials @ block_values
    running_max = new_max

streaming_read = numerator / denominator
dense_read = scores.softmax(0) @ values
torch.testing.assert_close(streaming_read, dense_read, atol=1e-12, rtol=1e-10)
print("stable blockwise softmax read matches dense softmax")
```

This particular example has finite scores and at least one allowed key. Empty or fully masked reads still need the explicit policy from 08.3.
