## 1. Motivation: one mixture can be restrictive

One attention head forms one distribution over keys for each query. A token may need several different relationships at once. Multiple heads allow several learned projections and attention distributions to read information in parallel.

Different heads are not assigned grammatical or semantic roles by the algorithm. They can specialize, overlap, or become redundant.

## 2. Choose the dimensions explicitly

Let model width be $D$, head count $h$, and per-head width $d_h=D/h$, assuming $h$ divides $D$. In this common design each head uses $d_k=d_v=d_h$.

For head $r$:

$$
\mathbf{Q}^{(r)}=\mathbf{X}(\mathbf{W}_Q^{(r)})^{\mathsf T},
\quad
\mathbf{K}^{(r)}=\mathbf{X}(\mathbf{W}_K^{(r)})^{\mathsf T},
\quad
\mathbf{V}^{(r)}=\mathbf{X}(\mathbf{W}_V^{(r)})^{\mathsf T}.
$$

Each weight $\mathbf{W}_Q^{(r)},\mathbf{W}_K^{(r)},\mathbf{W}_V^{(r)}$ has shape $(d_h,D)$; biases of length $d_h$ are omitted in these equations and included in the implementation. Each projected tensor has shape $(B,T,d_h)$. Its output is

$$
\mathbf{O}^{(r)}
=\operatorname{softmax}\left(
\frac{\mathbf{Q}^{(r)}(\mathbf{K}^{(r)})^{\mathsf T}}{\sqrt{d_h}}
\right)\mathbf{V}^{(r)}.
$$

Stacking heads gives $(B,h,T,d_h)$. Each head normalizes its own key scores.

## 3. Splitting a projection is not splitting raw tokens

Rather than launching $h$ small projection layers, compute one projection to width $D$. Divide the projected feature dimension into $h$ blocks.

The transformation is

```text
(B,T,D) → reshape (B,T,h,d_h) → transpose (B,h,T,d_h).
```

Reshape groups neighboring feature entries into heads. Transpose moves the head axis before time so matrix multiplication operates on $(T,d_h)$ per head. Omitting the transpose mixes the wrong axes.

For $B=1,T=2,D=4,h=2$, suppose a projected Q is

```text
token 0: [10, 11, 12, 13]
token 1: [20, 21, 22, 23]
```

After the correct reshape **and** transpose, head 0 sees rows `[10,11]` and `[20,21]`, while head 1 sees `[12,13]` and `[22,23]`. Directly reshaping to `(B,h,T,d_h)` would instead put both parts of token 0 into head 0. Shapes may look valid while token/head meaning is wrong.

The projection was learned **before** the split. Heads are not necessarily restricted to disjoint raw input features.

## 4. Merge outputs and learn their combination

Each query now has $h$ output vectors. Concatenate along the feature dimension to recover width $D$:

$$
\mathbf{C}
=\operatorname{Concat}(\mathbf{O}^{(1)},\ldots,\mathbf{O}^{(h)}),
\qquad
\mathbf{Y}=\mathbf{C}\mathbf{W}_O^{\mathsf T}+\mathbf{b}_O.
$$

The output projection $\mathbf{W}_O\in\mathbb{R}^{D\times D}$ mixes features from different heads.

In code, transpose back to $(B,T,h,d_h)$ before reshaping to $(B,T,D)$. `reshape` can copy a noncontiguous tensor when necessary; `view` requires compatible storage strides.

## 5. Parameter and attention-map counts

With all four projections using bias, the common design has $4D^2+4D$ parameters. Holding $D$ fixed while increasing $h$ does not multiply this projection parameter count.

However, the explicit attention weights have shape $(B,h,T,T)$. At fixed $D$, score/read arithmetic remains on the order of $BT^2D$, while stored probability maps grow with $h$ if materialized.

Different choices such as grouped-query attention change this accounting; 10.2 discusses them.

## 6. Runnable implementation and PyTorch reference comparison

```python
import math
import torch
from torch import nn

class MultiHeadSelfAttention(nn.Module):
    def __init__(self, width, heads):
        super().__init__()
        assert width % heads == 0
        self.width, self.heads, self.head_dim = width, heads, width // heads
        self.qkv = nn.Linear(width, 3 * width)
        self.out = nn.Linear(width, width)

    def forward(self, x):
        B, T, D = x.shape
        Q, K, V = self.qkv(x).chunk(3, dim=-1)
        def split(tensor):
            return tensor.reshape(B, T, self.heads, self.head_dim).transpose(1, 2)
        Q, K, V = split(Q), split(K), split(V)
        weights = (Q @ K.transpose(-2, -1) / math.sqrt(self.head_dim)).softmax(-1)
        read = weights @ V
        merged = read.transpose(1, 2).reshape(B, T, D)
        return self.out(merged), weights

torch.manual_seed(25)
model = MultiHeadSelfAttention(12, 3).double()
reference = nn.MultiheadAttention(12, 3, dropout=0.0, batch_first=True).double()
with torch.no_grad():
    reference.in_proj_weight.copy_(model.qkv.weight)
    reference.in_proj_bias.copy_(model.qkv.bias)
    reference.out_proj.weight.copy_(model.out.weight)
    reference.out_proj.bias.copy_(model.out.bias)

x1 = torch.randn(2, 5, 12, dtype=torch.float64, requires_grad=True)
x2 = x1.detach().clone().requires_grad_()
actual, attention = model(x1)
expected, expected_attention = reference(x2, x2, x2,
                                        need_weights=True, average_attn_weights=False)
torch.testing.assert_close(actual, expected, atol=1e-10, rtol=1e-8)
torch.testing.assert_close(attention, expected_attention, atol=1e-10, rtol=1e-8)
actual.square().sum().backward()
expected.square().sum().backward()
torch.testing.assert_close(x1.grad, x2.grad, atol=1e-10, rtol=1e-8)
for p, q in zip(model.parameters(), reference.parameters()):
    torch.testing.assert_close(p.grad, q.grad, atol=1e-10, rtol=1e-8)
assert sum(p.numel() for p in model.parameters()) == 4 * 12**2 + 4 * 12
print("output:", actual.shape, "per-head weights:", attention.shape)
print("forward, input gradients, and parameter gradients match PyTorch MultiheadAttention")
```

Identical parameters are essential for this comparison. Comparing two separately initialized modules would not verify implementation equivalence.

The code omits masking and dropout to isolate head mechanics. A production decoder needs a causal mask; 08.3 adds it.

The backward comparison is intentionally stronger than an output check: matching input gradients alone could still hide an error in how the packed projection parameters receive gradients. Matching every parameter gradient tests the split, per-head reads, merge, and output projection as one differentiable computation.

## 7. Experiments and pitfalls

Fix $D$ and vary $h$ among divisors. Compare per-head dimensions and parameter counts. Learning quality may change even when parameter count stays fixed.

Average weights across heads only for a clearly labeled visualization. Averaging is not how head outputs are computed: each head first reads its own projected values.

Attention dropout, when used, is usually applied to probabilities after softmax with inverted scaling during training. An individual dropped row need not sum to one. Evaluation and reference tests should disable dropout.
