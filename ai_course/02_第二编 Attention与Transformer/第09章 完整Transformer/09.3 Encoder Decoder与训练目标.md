> Prerequisites: 08.3, 09.2, and cross-entropy. Goal: choose architecture and visibility from the prediction task.

## 1. Motivation: architecture is organized around available information

A sentence classifier, a translation model, and a next-token generator need different visibility patterns. The presence of attention blocks alone does not define the task.

Specify what is observed and what must be predicted. Then define which positions may communicate and where losses are applied.

## 2. Three common arrangements

| Arrangement | Attention visibility | Typical prediction arrangement |
|---|---|---|
| Encoder-only | Often bidirectional self-attention over observed input | Classification, tagging, masked-input reconstruction |
| Decoder-only | Causal self-attention over a growing prefix | Autoregressive continuation |
| Encoder–decoder | Bidirectional source encoder; causal target self-attention; target-to-source cross-attention | Conditional sequence generation |

These are common patterns rather than exhaustive definitions. The objective is a separate choice: an encoder is not automatically trained by masked language modeling, and a decoder-only model can be used for classification too.

The original Transformer decoder includes cross-attention. “Decoder-only” language models usually omit that source cross-attention because everything is represented as one prefix.

## 3. Encoder–decoder data flow

Let source length be $S$ and target-input length be $T$. The encoder produces memory $\mathbf{M}\in\mathbb{R}^{B\times S\times D}$.

A target decoder block first performs causal self-attention over target states. In cross-attention, queries come from target states and keys/values from encoder memory. The score shape per head is $(T,S)$.

Source padding must be ignored both inside the encoder and when the decoder reads memory. Target causality prevents reading later target inputs; it does not prevent reading the complete observed source when that is allowed by the task.

## 4. Derive conditional sequence likelihood

Given observed source $\mathbf{x}$ and desired output tokens $y_1,\ldots,y_T$, the probability chain rule gives

$$
p(\mathbf{y}\mid\mathbf{x})
=\prod_{t=1}^{T}p(y_t\mid y_{<t},\mathbf{x}).
$$

For just three output tokens, expand the rule before introducing the loss:

$$
p(y_1,y_2,y_3\mid\mathbf{x})
=p(y_1\mid\mathbf{x})
 p(y_2\mid y_1,\mathbf{x})
 p(y_3\mid y_1,y_2,\mathbf{x}).
$$

Taking $-\log$ changes this product into a sum, because $\log(ab)=\log a+\log b$. Each summand is the negative log probability assigned to the correct next token, exactly the categorical cross-entropy from Part I. No independence of output tokens is assumed; earlier tokens appear in the conditioning.

Negative log likelihood is a sum of conditional next-token losses. Teacher forcing supplies the true earlier output tokens during training:

```text
target input:  [BOS, y1, y2, ...]
target label:  [y1,  y2, y3, ...]
```

BOS starts prediction before the first target token. EOS can teach when generation should end. PAD is batching filler, with a distinct role.

For valid-target mask $m_{n,t}$, average only the intended supervised terms:

$$
L=-\frac{\sum_{n,t}m_{n,t}\log p(y_{n,t}\mid y_{n,<t},\mathbf{x}_n)}
{\sum_{n,t}m_{n,t}}.
$$

Here $n$ indexes examples, $t$ indexes target positions, and $m_{n,t}\in\{0,1\}$ selects supervised tokens. The denominator must be nonzero; an all-ignored batch needs to be skipped or handled explicitly.

For two sequences with token losses $[1,1]$ and $[4]$, valid-token averaging gives $(1+1+4)/3=2$, while averaging the two sequence means gives $(1+4)/2=2.5$. Both can be defined deliberately, but they weight data differently.

Specify whether evaluation averages tokens or first averages per sequence; unequal lengths make those different metrics. With `cross_entropy(logits, labels, ignore_index=PAD)`, pass raw logits and arrange the class axis as expected; do not apply softmax first.

## 5. Parallel training is compatible with causal generation

During teacher-forced training, all correct previous target tokens are already known. A causal mask lets all target positions be computed in parallel while restricting each position's information.

During generation, the next token is unknown until predicted or sampled. Feed it back before predicting the following token. Autoregressive generation is sequential across output tokens even though each forward pass uses parallel numerical kernels.

An unshifted target can create a trivial identity problem: each position reads its own input and is asked to reproduce it. A diagonal-allowed mask is correct only with the intended shifted prediction task.

## 6. Runnable shape and causality check for encoder–decoder attention

This example constructs a randomly initialized encoder–decoder with PyTorch. It verifies information flow; 09.4 builds and trains a smaller decoder from first principles.

```python
import torch
from torch import nn

torch.manual_seed(29)
torch.set_num_threads(1)
B, S, T, D = 2, 4, 5, 12
transformer = nn.Transformer(
    d_model=D, nhead=3, num_encoder_layers=1, num_decoder_layers=1,
    dim_feedforward=24, dropout=0.0, batch_first=True,
).double().eval()

source = torch.randn(B, S, D, dtype=torch.float64)
target_input = torch.randn(B, T, D, dtype=torch.float64)
source_pad = torch.tensor([[False, False, False, True],
                           [False, False, False, False]])
target_block = torch.ones(T, T, dtype=torch.bool).triu(1)
with torch.no_grad():
    output = transformer(source, target_input, tgt_mask=target_block,
                         src_key_padding_mask=source_pad,
                         memory_key_padding_mask=source_pad)

    changed_target = target_input.clone()
    changed_target[:, 3:] += 10 * torch.randn_like(changed_target[:, 3:])
    changed_output = transformer(source, changed_target, tgt_mask=target_block,
                                 src_key_padding_mask=source_pad,
                                 memory_key_padding_mask=source_pad)
    torch.testing.assert_close(output[:, :3], changed_output[:, :3],
                               atol=1e-9, rtol=1e-7)

    changed_source = source.clone()
    changed_source[0, -1] += 10 * torch.randn_like(changed_source[0, -1])
    padding_output = transformer(changed_source, target_input, tgt_mask=target_block,
                                  src_key_padding_mask=source_pad,
                                  memory_key_padding_mask=source_pad)
    torch.testing.assert_close(output[0], padding_output[0], atol=1e-9, rtol=1e-7)

assert output.shape == (B, T, D)
labels = torch.tensor([[3, 4, 2, 0], [5, 2, 0, 0]])  # 0=PAD, 1=BOS, 2=EOS
decoder_ids = torch.cat([torch.ones(B, 1, dtype=torch.long), labels[:, :-1]], dim=1)
print("decoder input:", decoder_ids)
print("target labels:", labels)
print("encoder-decoder output:", output.shape)
```

The floating feature tensors above test visibility only. `nn.Transformer` does not create token embeddings, position embeddings, a vocabulary head, label shifting, or a loss for you; a language model must supply those pieces. Section 09.4 does so explicitly for a small decoder.

Perturbations change individual features, not merely a common feature offset that normalization might remove. The companion script includes negative controls: removing the target causal mask makes future perturbations detectable, and removing the source masks makes the padded-source perturbation detectable. These controls help distinguish true masking from an accidentally insensitive test input.

The perturbation checks compare real allowed outputs, not padded encoder output rows themselves. A masked source query may still produce a representation; the decoder must not read it.

## 7. Decoding and evaluation limits

Greedy decoding chooses the largest logit. Sampling uses the predicted distribution, optionally changed by temperature or truncation. Beam search tracks several partial sequences. These are output procedures, not different training architectures.

Teacher-forced token accuracy and free-running sequence accuracy measure different behaviors. A generated mistake changes the next input context, potentially causing further errors.

A low held-out loss on a synthetic task does not demonstrate general language ability. Chapter 11 introduces language data and objectives more systematically.
