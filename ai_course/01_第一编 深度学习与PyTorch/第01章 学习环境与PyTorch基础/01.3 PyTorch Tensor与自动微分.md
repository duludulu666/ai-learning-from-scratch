## 1. Why autograd is needed

A network may contain millions of parameters. Manually deriving and programming every partial derivative would be difficult to maintain. Automatic differentiation applies the chain rule to the operations actually executed in the forward pass.

Autograd is not a symbolic algebra solver and does not estimate every derivative by repeatedly perturbing parameters. It reuses the derivatives of elementary operations and combines them along a recorded computation graph.

## 2. Values, devices, and dtypes

A tensor has a shape, dtype, and device. Floating-point features usually use `float32`; class indices use `long`. A CPU tensor cannot generally participate in a matrix multiplication with a CUDA tensor. Move the model and inputs to the same device.

`torch.from_numpy` shares CPU storage with a compatible NumPy array; `torch.tensor(array)` copies it. Converting an existing tensor with `torch.tensor(existing_tensor)` creates a new tensor disconnected from the original computation graph. Use the original tensor when you need its history.

## 3. Derive a small graph before using the API

Take $x=2$ and define $u=x^2$, $v=3u$, $r=2x$, and $L=v+r+1$. There are two paths from $x$ to $L$.

The square path contributes

$$
\frac{\partial L}{\partial v}
\frac{\partial v}{\partial u}
\frac{\partial u}{\partial x}
=1\cdot3\cdot2x=6x.
$$

The other path contributes $1\cdot2=2$. Adding the paths gives

$$
\frac{\mathrm{d}L}{\mathrm{d}x}=6x+2=14.
$$

A graph with branching must **sum contributions**. Backpropagation is not just multiplying a single sequence of derivatives.

## 4. What backward stores

A leaf tensor is typically a tensor directly created by the user with `requires_grad=True`. Its gradient is accumulated in `.grad`. Model weights created as `nn.Parameter` are leaves registered with their module.

An intermediate such as $u=x^2$ is a non-leaf. Its derivative is used internally, but its `.grad` is not retained by default. Call `u.retain_grad()` before backward when you want to inspect it.

The forward pass usually creates a new graph each iteration. By default, backward frees saved intermediates once used. To do another ordinary training iteration, run forward again. Calling backward twice on the same freed graph can raise an error; `retain_graph=True` is usually unnecessary for a standard training loop.

## 5. Why a vector output needs an upstream gradient

If $\mathbf{y}\in\mathbb{R}^{O}$, “the derivative of $\mathbf{y}$” is a Jacobian, not one gradient vector. `y.backward(v)` computes the gradient of the scalar $\mathbf{v}^{\mathsf T}\mathbf{y}$, treating $\mathbf{v}$ as the supplied upstream weights.

For $y_i=x_i^2$ and $\mathbf{v}=[1,3]^{\mathsf T}$:

$$
L=x_1^2+3x_2^2,
\qquad
\nabla_{\mathbf{x}}L=[2x_1,6x_2]^{\mathsf T}.
$$

Providing ones is equivalent to differentiating the sum of outputs. It is not the complete Jacobian.

## 6. Gradient computation and parameter updates are separate

`loss.backward()` computes gradients at the current parameters. It does not lower the loss by itself. `optimizer.step()` uses the stored gradients to update parameters. `optimizer.zero_grad()` clears gradients from previous computations.

Gradients accumulate because a parameter may contribute to several losses or micro-batches. For ordinary mini-batch training, clear them once before each new update. When accumulating unequal micro-batches, average by the intended total sample count, not blindly by the number of micro-batches.

For micro-batches of 2 and 1 examples, let their mean losses be $L_1,L_2$. The full three-example mean is $(2L_1+L_2)/3$, not $(L_1+L_2)/2$. To reproduce its gradient, call backward on $(2/3)L_1$ and $(1/3)L_2$ without clearing between them, then step once.

This equivalence assumes the same per-example computation at fixed parameters. BatchNorm across different micro-batches, different dropout masks, or stepping between backward calls can change the computation. Accumulation does not automatically simulate every behavior of a larger batch.

Chapter 04 explains why and when a gradient-based update decreases the loss.

## 7. Evaluation, detaching, and safe manual updates

`model.eval()` changes behaviors such as dropout and BatchNorm; it does not turn off autograd. `torch.no_grad()` turns off recording; it does not set evaluation mode.

`detach()` returns a tensor disconnected from the graph and normally sharing storage. It is useful for logging or deliberate gradient boundaries. `clone()` copies storage but preserves the graph; `detach().clone()` does both a copy and a gradient cut. Storage independence and gradient connectivity are separate questions: a clone has independent storage but remains connected; a detached view shares storage but cuts the derivative path. If you detach a prediction before the loss, you prevent the loss from teaching the earlier model.

Manual parameter updates belong inside `torch.no_grad()`. Avoid `.data` mutations because they can bypass checks that protect gradient correctness.

## 8. Runnable experiment: inspect and verify the graph

```python
import torch

previous_dtype = torch.get_default_dtype()
torch.set_default_dtype(torch.float64)

x = torch.tensor(2.0, requires_grad=True)
u = x.square()
u.retain_grad()
loss = 3 * u + 2 * x + 1
loss.backward()
torch.testing.assert_close(x.grad, torch.tensor(14.0))
torch.testing.assert_close(u.grad, torch.tensor(3.0))

# A fresh graph, but the same leaf: gradients add.
loss_again = 3 * x.square() + 2 * x + 1
loss_again.backward()
torch.testing.assert_close(x.grad, torch.tensor(28.0))
x.grad = None

# Finite differences verify this scalar derivative independently.
def f(value):
    return 3 * value**2 + 2 * value + 1

eps = 1e-5
numeric = (f(2.0 + eps) - f(2.0 - eps)) / (2 * eps)
assert abs(numeric - 14.0) < 1e-8
print("finite difference:", numeric)

z = torch.tensor([1., 2.], requires_grad=True)
y = z.square()
y.backward(torch.tensor([1., 3.]))
torch.testing.assert_close(z.grad, torch.tensor([2., 12.]))

model = torch.nn.Linear(2, 1)
model.eval()
print("eval alone tracks gradients:", model(torch.ones(1, 2)).requires_grad)
with torch.no_grad():
    print("no_grad tracks gradients:", model(torch.ones(1, 2)).requires_grad)

torch.set_default_dtype(previous_dtype)
```

The companion script additionally checks that `clone()` preserves a gradient path, `detach().clone()` removes it, and correctly weighted unequal micro-batches match a full-batch gradient for a deterministic affine model.

The finite-difference answer should be close to 14; it is a check, not the method autograd uses. For gradient checks use double precision and avoid nondifferentiable points such as ReLU at zero.

## 9. Experiments and common mistakes

Deliberately replace a differentiable intermediate with a detached tensor. Inspect which parameters now have `grad is None`. Distinguish “no path to this loss” from an existing path whose numerical gradient happens to be zero.

Do not call `item()` on a value needed to calculate a differentiable loss; it extracts a Python scalar. Calling it for logging after constructing the loss is fine.
