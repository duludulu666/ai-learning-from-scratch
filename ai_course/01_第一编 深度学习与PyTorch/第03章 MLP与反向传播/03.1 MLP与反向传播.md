## Motivation

A Multi-Layer Perceptron (MLP) is a neural network composed of affine transformations and nonlinear activations. A single affine layer models only linear relationships; nonlinear activations let the network represent complex functions.

## Linear layer

For one sample:

$$
\mathbf{y}=\mathbf{W}\mathbf{x}+\mathbf{b}.
$$

- $\mathbf{x}$: input vector, shape `(in_features,)`
- $\mathbf{W}$: weight matrix, shape `(out_features, in_features)`
- $\mathbf{b}$: bias vector, shape `(out_features,)`
- $\mathbf{y}$: output vector, shape `(out_features,)`

Each row of $\mathbf{W}$ belongs to one output neuron. For a batch $\mathbf{X}$, PyTorch computes the equivalent of:

$$
\mathbf{Y}=\mathbf{X}\mathbf{W}^{\mathsf T}+\mathbf{b}.
$$

Thus `nn.Linear(10, 6)` stores `weight.shape == (6, 10)` and produces `(batch_size, 6)`. In NumPy, `@` is matrix multiplication and `*` is element-wise multiplication. The bias is broadcast across every sample.

## Two-layer MLP

For input width $D$, hidden width $H$, and output width $O$, the first layer has $\mathbf{W}_1:(H,D)$ and $\mathbf{b}_1:(H,)$; the second has $\mathbf{W}_2:(O,H)$ and $\mathbf{b}_2:(O,)$. The intermediate vectors $\mathbf{h},\mathbf{a}$ each have length $H$. Here $\mathbf{h}$ is a pre-activation, not a separate trainable parameter.

The forward pass is:

$$
\begin{aligned}
\mathbf{h}&=\mathbf{W}_1\mathbf{x}+\mathbf{b}_1,\\
\mathbf{a}&=\mathrm{ReLU}(\mathbf{h}),\\
\mathbf{y}&=\mathbf{W}_2\mathbf{a}+\mathbf{b}_2.
\end{aligned}
$$

Without ReLU, two affine layers collapse into one:

$$
\mathbf{W}_2(\mathbf{W}_1\mathbf{x}+\mathbf{b}_1)+\mathbf{b}_2
=(\mathbf{W}_2\mathbf{W}_1)\mathbf{x}+(\mathbf{W}_2\mathbf{b}_1+\mathbf{b}_2).
$$

ReLU introduces nonlinearity:

$$
\mathrm{ReLU}(z)=\max(0,z).
$$

Its derivative is $1$ for positive values and $0$ for negative values, so a negative pre-activation blocks the gradient through this ReLU for that sample. ReLU is not differentiable at zero; PyTorch and the mask below use zero there.

### A nonlinear function two affine layers cannot reproduce

Consider binary inputs $(x_1,x_2)$ and XOR: output 1 when exactly one input equals 1, and 0 otherwise. If an affine function $w_1x_1+w_2x_2+b$ matched all four labels, $(0,0)$ would force $b=0$, and $(1,0),(0,1)$ would force $w_1=w_2=1$. It would then output 2, not 0, at $(1,1)$.

Two ReLU features can represent these four targets exactly:

$$
a_1=\mathrm{ReLU}(x_1-x_2),\quad
a_2=\mathrm{ReLU}(x_2-x_1),\quad
y=a_1+a_2.
$$

For the four binary inputs, the outputs are $0,1,1,0$. This is a representational example, not proof that a particular optimizer will discover these weights. ReLU networks are piecewise affine: the active-unit pattern determines which affine expression applies.

## Loss and gradient descent

For target $\mathbf{t}$, use:

$$
L=\frac{1}{2}\lVert\mathbf{y}-\mathbf{t}\rVert_2^2.
$$

The optimizer uses these gradients to propose a small move opposite to the local increase in loss. This gives the gradient-descent update below; 04.1 derives its direction and step-size limits. A step is not guaranteed to reduce every batch's loss.

Gradient descent updates:

$$
\boldsymbol{\theta}\leftarrow\boldsymbol{\theta}-\eta\nabla_{\boldsymbol{\theta}}L.
$$

Conceptually, with model, data, loss and optimizer already defined (pseudocode, not a standalone program):

```text
optimizer.zero_grad()
prediction = model(x)
loss = criterion(prediction, target)
loss.backward()
optimizer.step()
```

`backward()` computes gradients; `step()` updates parameters. Gradients accumulate by default, so `zero_grad()` is needed.

## Backpropagation

Before writing the vector equations, track one scalar path. For output coordinate $y_i$ and second-layer weight $W^{(2)}_{ij}$,

$$
\frac{\partial L}{\partial W^{(2)}_{ij}}
=
\underbrace{\frac{\partial L}{\partial y_i}}_{\text{loss sensitivity}}
\underbrace{\frac{\partial y_i}{\partial W^{(2)}_{ij}}}_{a_j}
=
\frac{\partial L}{\partial y_i}a_j.
$$

The matrix form is an outer product because every output sensitivity combines with every hidden activation. A shared bias is used by every example, so its batch gradient will be a sum over the batch rather than a per-example vector.

The equations below summarize the backward pass. For their chain-rule derivation and numerical example, read 03.2 next. In this section, the notation $\mathrm{d}\mathbf{z}$ is shorthand for the loss gradient with respect to $\mathbf{z}$, not a small change in its value.

For the squared-error loss, let:

$$
\mathrm{d}\mathbf{y}=\frac{\partial L}{\partial\mathbf{y}}=\mathbf{y}-\mathbf{t}.
$$

$$
\begin{aligned}
\mathrm{d}\mathbf{W}_2&=\mathrm{d}\mathbf{y}\,\mathbf{a}^{\mathsf T},\\
\mathrm{d}\mathbf{b}_2&=\mathrm{d}\mathbf{y},\\
\mathrm{d}\mathbf{a}&=\mathbf{W}_2^{\mathsf T}\mathrm{d}\mathbf{y},\\
\mathrm{d}\mathbf{h}&=\mathrm{d}\mathbf{a}\odot\mathbf{1}_{\{\mathbf{h}>0\}},\\
\mathrm{d}\mathbf{W}_1&=\mathrm{d}\mathbf{h}\,\mathbf{x}^{\mathsf T},\\
\mathrm{d}\mathbf{b}_1&=\mathrm{d}\mathbf{h}.
\end{aligned}
$$

Each parameter gradient has the same shape as its parameter. For $\mathbf{x}:(4,)$, $\mathbf{h}:(5,)$, and $\mathbf{y}:(2,)$: $\mathrm{d}\mathbf{W}_2:(2,5)$, $\mathrm{d}\mathbf{b}_2:(2,)$, $\mathrm{d}\mathbf{W}_1:(5,4)$, and $\mathrm{d}\mathbf{b}_1:(5,)$.

## NumPy implementation

```python
import numpy as np

def relu(z):
    return np.maximum(0.0, z)

def mlp_forward(x, W1, b1, W2, b2):
    h = W1 @ x + b1
    a = relu(h)
    y = W2 @ a + b2
    return y, (x, h, a, W1, W2)

def mlp_backward(y, target, cache):
    x, h, a, W1, W2 = cache
    dy = y - target
    dW2 = np.outer(dy, a)
    db2 = dy.copy()
    da = W2.T @ dy
    dh = da * (h > 0)
    dW1 = np.outer(dh, x)
    db1 = dh.copy()
    return dW1, db1, dW2, db2
```

`np.outer(u,v)` creates a matrix with entries `u[i]*v[j]`, the weight-gradient structure for a linear layer.

## PyTorch implementation

```python
import torch
from torch import nn

class TinyMLP(nn.Module):
    def __init__(self, in_features=4, hidden_features=5, out_features=2):
        super().__init__()
        self.layer1 = nn.Linear(in_features, hidden_features)
        self.layer2 = nn.Linear(hidden_features, out_features)

    def forward(self, x):
        h = self.layer1(x)
        a = torch.relu(h)
        return self.layer2(a)

torch.manual_seed(301)
model = TinyMLP()
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
x = torch.randn(8, 4)
target = torch.randn(8, 2)
optimizer.zero_grad()
prediction = model(x)
loss = 0.5 * (prediction - target).square().sum(dim=-1).mean()
loss.backward()
optimizer.step()
```

The batch code averages per-example half-squared sums over output coordinates. Standard `MSELoss` instead averages all output elements with no factor $1/2$. Specify the reduction before comparing gradient values.

## Runnable gradient verification

Run this block after the NumPy functions above. It uses identical parameters and the same scalar loss in NumPy and PyTorch.

```python
import numpy as np
import torch

rng = np.random.default_rng(3)
x_check = rng.normal(size=4)
W1_check = rng.normal(size=(5, 4))
b1_check = rng.normal(size=5)
W2_check = rng.normal(size=(2, 5))
b2_check = rng.normal(size=2)
target_check = rng.normal(size=2)
y_check, cache_check = mlp_forward(x_check, W1_check, b1_check, W2_check, b2_check)
manual_grads = mlp_backward(y_check, target_check, cache_check)

params = [torch.tensor(a, requires_grad=True)
          for a in [W1_check, b1_check, W2_check, b2_check]]
tw1, tb1, tw2, tb2 = params
tx = torch.tensor(x_check)
prediction_check = tw2 @ torch.relu(tw1 @ tx + tb1) + tb2
loss_check = 0.5 * (prediction_check - torch.tensor(target_check)).square().sum()
loss_check.backward()
for manual_grad, parameter in zip(manual_grads, params):
    np.testing.assert_allclose(manual_grad, parameter.grad.numpy(), atol=1e-12)
print("all four parameter gradients match")
```

### Input gradients are part of the same chain

The NumPy helper returns four parameter gradients because those are needed for this optimizer example. A preceding layer would also need

$$
\nabla_{\mathbf{x}}L=\mathbf{W}_1^{\mathsf T}\mathrm{d}\mathbf{h}.
$$

This is how several MLP blocks can be connected. The companion checks both the parameter gradients and this input gradient, and checks a weight with central differences away from a ReLU corner.

## Common mistakes

1. Confusing model output `y` with target `t`.
2. Treating `backward()` as the parameter update.
3. Forgetting gradient accumulation and `zero_grad()`.
4. Reversing PyTorch's stored shape `(out_features, in_features)`.
5. Using `*` instead of `@` for matrix multiplication.
6. Forgetting the ReLU derivative mask.
