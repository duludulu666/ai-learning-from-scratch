> Prerequisite: 02.1 and basic derivatives of exponential/logarithm. Goal: derive the classification loss and its logit gradient.

## 1. Motivation: classification needs comparable scores

A $K$-class classifier must choose among $K$ alternatives. Give each class one affine score:

$$
\mathbf{z}=\mathbf{W}\mathbf{x}+\mathbf{b},
\qquad
\mathbf{W}\in\mathbb{R}^{K\times D},
\quad \mathbf{z}\in\mathbb{R}^{K}.
$$

The entries $z_k$ are **logits**. They may be negative and do not sum to one. Their ordering determines the predicted class, but we also want a normalized probability model for learning.

## 2. Constructing softmax

We want positive values that grow with each score, so exponentiate the logits. Divide by their sum to normalize:

$$
p_k=\frac{\exp(z_k)}{\sum_{j=1}^{K}\exp(z_j)}.
$$

Now $p_k>0$ and $\sum_k p_k=1$. Equal logits give equal probabilities. Larger differences in logits produce more concentrated predictions.

Adding the same scalar $c$ to all logits multiplies every numerator and the denominator by $\exp(c)$, which cancels. Only relative logits matter.

For $\mathbf{z}=[2,1,0]^{\mathsf T}$, the probabilities are approximately $[0.665,0.245,0.090]^{\mathsf T}$. Doubling logits generally changes probabilities; adding a constant does not.

## 3. Why the loss is the negative logarithm of the correct probability

For an observed class $y$, our model assigns likelihood $p_y$. Learning should increase the probability of observed labels. Across independent labeled examples, maximize the product of their assigned probabilities.

Products of many small probabilities can underflow. The logarithm is increasing, so maximizing the log of that product preserves its maximizer and gives a sum of logs. Turning maximization into minimization gives

$$
L=-\frac{1}{B}\sum_{i=1}^{B}\log p_{i,y_i}.
$$

For one example, a correct-class probability of $0.9$ gives loss about $0.105$, while $0.01$ gives about $4.605$. Confidence in a wrong answer is strongly penalized.

## 4. Cross-entropy and target distributions

Let $\mathbf{t}\in\mathbb{R}^{K}$ be a target probability distribution, with nonnegative entries summing to one. Cross-entropy is

$$
H(\mathbf{t},\mathbf{p})=-\sum_k t_k\log p_k.
$$

A hard label corresponds to one-hot $\mathbf{t}$, so this becomes $-\log p_y$. A soft target may represent label smoothing or a teacher model.

For fixed $\mathbf{t}$,

$$
H(\mathbf{t},\mathbf{p})
=H(\mathbf{t})+D_{\mathrm{KL}}(\mathbf{t}\|\mathbf{p}).
$$

This identity is an expansion, not a new objective. Define $H(\mathbf{t})=-\sum_k t_k\log t_k$ and $D_{\mathrm{KL}}(\mathbf{t}\|\mathbf{p})=\sum_k t_k\log(t_k/p_k)$, using $0\log0=0$ by a limit. Adding cancels the $t_k\log t_k$ terms, leaving $-\sum_k t_k\log p_k$.

The first term is independent of the classifier. Minimizing cross-entropy therefore minimizes this direction of KL divergence. You need not memorize information-theory terminology to implement the hard-label case, but the probability interpretation is useful later for language modeling.

## 5. Stable calculation before differentiation

Direct exponentiation of a logit such as 1000 can overflow. Since common shifts cancel, subtract the maximum logit before exponentiation.

For the loss it is even better to keep the computation in log space. Rewrite

$$
\ell=-z_y+\log\sum_j\exp(z_j).
$$

For $m=\max_j z_j$,

$$
\log\sum_j\exp(z_j)
=m+\log\sum_j\exp(z_j-m).
$$

This is log-sum-exp. `CrossEntropyLoss` uses a stable combined computation. Calculating probabilities, rounding them to zero, and then taking a logarithm loses stability.

## 6. Derive the logit gradient step by step

Write the loss with a target distribution:

$$
\ell=-\sum_k t_k z_k+\log\sum_j\exp(z_j),
$$

where we used $\sum_k t_k=1$. Differentiate with respect to one logit $z_r$.

The first term contributes $-t_r$. In the second term, let $s=\sum_j\exp(z_j)$. The derivative of $\log s$ is $s^{-1}\partial s/\partial z_r$, and $\partial s/\partial z_r=\exp(z_r)$. Therefore

$$
\frac{\partial\ell}{\partial z_r}
=-t_r+\frac{\exp(z_r)}{\sum_j\exp(z_j)}
=p_r-t_r.
$$

For a hard target, the correct class has gradient $p_y-1\leq0$; incorrect classes have positive gradients. If logits were independent optimization variables, subtracting this gradient would raise the correct logit and lower the others. Actual model parameters are shared across examples and coordinates, so a parameter update does not promise that every individual example's logits move this way. The logits' gradient entries sum to zero, matching softmax's invariance to adding a common constant.

For logits $(\log2,0,0)$ and hard target class 1 under zero-based indexing, probabilities are $(0.5,0.25,0.25)$ and the gradient is $(0.5,-0.75,0.25)$. With soft target $(0.1,0.8,0.1)$, the same prediction instead gives gradient $(0.4,-0.55,0.15)$. The companion script checks a genuinely soft target, not only a floating-point one-hot vector.

For batched logits $\mathbf{Z}\in\mathbb{R}^{B\times K}$, define $\mathbf{G}=(\mathbf{P}-\mathbf{T})/B$. Since $\mathbf{Z}=\mathbf{X}\mathbf{W}^{\mathsf T}+\mathbf{b}$,

$$
\nabla_{\mathbf{W}}L=\mathbf{G}^{\mathsf T}\mathbf{X},
\qquad
\nabla_{\mathbf{b}}L=\sum_i\mathbf{G}_{i,:}.
$$

The input gradient is $\nabla_{\mathbf{X}}L=\mathbf{G}\mathbf{W}$ with shape $(B,D)$; it carries the classification loss to an earlier feature extractor. The division by batch size appears once, because the loss averages examples.

## 7. Runnable experiment: stable NumPy and PyTorch agree

```python
import numpy as np
import torch
import torch.nn.functional as F

logits = np.array([[2., 1., 0.], [1000., 999., 998.]], dtype=np.float64)
labels = np.array([0, 2])
shifted = logits - logits.max(axis=1, keepdims=True)
log_probs = shifted - np.log(np.exp(shifted).sum(axis=1, keepdims=True))
probs = np.exp(log_probs)
manual_loss = -log_probs[np.arange(2), labels].mean()
one_hot = np.eye(3)[labels]
manual_grad = (probs - one_hot) / 2

z = torch.tensor(logits, requires_grad=True)
targets = torch.tensor(labels, dtype=torch.long)
loss = F.cross_entropy(z, targets)
loss.backward()
np.testing.assert_allclose(loss.item(), manual_loss)
np.testing.assert_allclose(z.grad.numpy(), manual_grad)

soft_targets = F.one_hot(targets, num_classes=3).to(z.dtype)
torch.testing.assert_close(F.cross_entropy(z.detach(), soft_targets), loss.detach())
torch.testing.assert_close(F.cross_entropy(z.detach() + 123.0, targets), loss.detach())
print("probabilities:\n", probs)
print("loss:", loss.item())
print("gradient:\n", z.grad)

torch.manual_seed(3)
X = torch.randn(90, 2, dtype=torch.float64)
y = (X[:, 0] + 0.5 * X[:, 1] > 0).long()
model = torch.nn.Linear(2, 2).double()
optimizer = torch.optim.SGD(model.parameters(), lr=0.3)
for _ in range(120):
    optimizer.zero_grad(set_to_none=True)
    train_loss = F.cross_entropy(model(X), y)
    train_loss.backward()
    optimizer.step()
print("training accuracy:", (model(X).argmax(-1) == y).double().mean().item())
```

The first two examples intentionally have very different absolute logit scales but the same relative scores. The classifier is a training demonstration; add a held-out split before reporting generalization.

## 8. API details and misconceptions

For hard labels, logits are `(B, K)` and labels are `(B,)` with `torch.long`. For soft targets, both logits and targets are `(B, K)` and targets are floating point. Modern PyTorch supports both; valid probability targets are your responsibility.

Do not pass softmax probabilities where the loss expects logits. That applies another normalization and changes the intended gradient.

Softmax regression has linear decision boundaries in the given feature space. High accuracy does not imply well-calibrated probabilities. For independent multi-label decisions, use independent sigmoid outputs with `BCEWithLogitsLoss`, not a softmax that forces classes to compete.
