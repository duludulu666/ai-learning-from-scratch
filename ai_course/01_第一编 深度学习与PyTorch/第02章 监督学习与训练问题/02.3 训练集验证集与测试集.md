## 1. Motivation: success on remembered examples is insufficient

Training deliberately adapts a model to its examples. Evaluating only those examples therefore answers a limited question: how well does the model fit information it has already used?

We want to estimate performance on future examples. A split creates data with different roles:

| Split | Used for | May guide parameter updates? |
|---|---|---|
| Training | Fit weights and preprocessing statistics | Yes |
| Validation | Select learning rate, model, threshold, stopping epoch | Not through ordinary backpropagation |
| Test | Final evaluation after choices are fixed | No |

Validation still influences the final model through selection. Repeatedly selecting from many candidates can overfit validation too. A test repeatedly inspected to guide changes has effectively become validation.

## 2. First choose the independent unit

A random split assumes the examples being separated represent sufficiently independent units from the intended distribution.

For a collection of images from the same object, frames from the same video, or measurements from the same subject, individual records may share highly specific information. Split by object, video, or subject when deployment requires generalizing to unseen ones.

For forecasting, split chronologically and ensure input windows and targets do not cross boundaries in a way that leaks future information. Training on future records to predict past ones evaluates a different task.

Stratification maintains class proportions. It does not automatically prevent group or temporal leakage. If these requirements conflict, the deployment unit takes priority and the resulting class counts must be inspected.

## 3. Fit preprocessing on training data

For feature $j$, estimate the training mean $\mu_j$ and standard deviation $s_j$:

$$
\mu_j=\frac{1}{N_{\mathrm{train}}}\sum_{i\in\mathrm{train}}x_{ij},
\qquad
\tilde x_{ij}=\frac{x_{ij}-\mu_j}{\max(s_j,\varepsilon)}.
$$

Here $s_j=\sqrt{N_{\mathrm{train}}^{-1}\sum_{i\in\mathrm{train}}(x_{ij}-\mu_j)^2}$ and $\varepsilon>0$ provides a minimum denominator. This matches `np.maximum(std, 1e-8)` in the code. Adding $\varepsilon$ is another convention, but is not exactly the same formula. Apply the same stored values to validation and test.

Re-estimating validation normalization from its own full distribution changes the evaluation procedure. Using all splits to fit feature selection, vocabulary, imputation, or scaling can also leak information.

## 4. Derive metrics from error counts

For binary classification, “positive” must first be defined. A true positive (TP) is a detected positive example; a false positive (FP) is a negative example incorrectly flagged. FN is a missed positive; TN is a correctly rejected negative.

Accuracy counts correct predictions among all examples:

$$
\mathrm{Accuracy}=\frac{TP+TN}{TP+FP+FN+TN}.
$$

Precision asks what fraction of alerts were correct, while recall asks what fraction of actual positives were found:

$$
\mathrm{Precision}=\frac{TP}{TP+FP},
\qquad
\mathrm{Recall}=\frac{TP}{TP+FN}.
$$

When both matter, the harmonic mean emphasizes the weaker value:

$$
F_1=\frac{2PR}{P+R}
=\frac{2TP}{2TP+FP+FN}.
$$

Specify a convention when a denominator is zero. A metric library may return zero or mark a value undefined; silently changing conventions makes comparisons unreliable.

Example: among 100 examples, 10 are positive. If $TP=8$, $FP=4$, $FN=2$, and $TN=86$, accuracy is 94%, precision is $8/12$, recall is $8/10$, and $F_1=16/22$.

An always-negative classifier gets 90% accuracy here but detects no positives.

The confusion matrix uses rows for truth and columns for prediction:

$$
\mathbf{C}=\begin{bmatrix}TN&FP\crFN&TP\end{bmatrix}
=\begin{bmatrix}86&4\cr2&8\end{bmatrix}.
$$

The positive column counts alerts, so precision divides by its sum, $4+8$. The positive row counts actual positives, so recall divides by its sum, $2+8$. This lets you reconstruct the formulas instead of memorizing four abbreviations.

The experiment defines precision/recall/F1 as zero when their denominator is zero. With no positive predictions, precision is mathematically undefined; reporting zero is an explicit reporting convention, not a measured precision of a nonempty alert set.

## 5. Thresholds, ranking, and class imbalance

A model often produces a positive score $s_i$, then predicts positive when $s_i\geq\tau$. Changing threshold $\tau$ changes precision and recall without retraining.

Choose thresholds on validation according to the actual decision cost. Do not choose the best threshold on test and report that as an untouched test result.

ROC curves show true-positive rate against false-positive rate. Precision–recall curves are often more revealing when positives are rare. An apparently small false-positive rate applied to a huge negative population can still produce many false alerts.

AUROC and PR-based summaries measure ranking across thresholds, not performance at one deployed threshold. They also do not measure calibration: predicted 90% confidence is calibrated only if such predictions are correct about 90% of the time under the assessed distribution.

## 6. Runnable experiment: reproducible groups and a confusion matrix

```python
import numpy as np
import torch
from torch.utils.data import TensorDataset, DataLoader

rng = np.random.default_rng(5)
groups = np.repeat(np.arange(12), 4)  # Four related records per group
group_order = rng.permutation(12)
train_groups, val_groups, test_groups = np.split(group_order, [8, 10])
train_idx = np.flatnonzero(np.isin(groups, train_groups))
val_idx = np.flatnonzero(np.isin(groups, val_groups))
test_idx = np.flatnonzero(np.isin(groups, test_groups))

assert set(groups[train_idx]).isdisjoint(groups[val_idx])
assert set(groups[train_idx]).isdisjoint(groups[test_idx])
assert set(groups[val_idx]).isdisjoint(groups[test_idx])

X = rng.normal(size=(48, 3))
X[val_idx] += 1.0  # A deliberate validation distribution shift
mean = X[train_idx].mean(axis=0)
std = X[train_idx].std(axis=0)
normalized = (X - mean) / np.maximum(std, 1e-8)
np.testing.assert_allclose(normalized[train_idx].mean(axis=0), 0, atol=1e-14)
print("validation feature means:", normalized[val_idx].mean(axis=0))

truth = np.array([1, 1, 1, 1, 0, 0, 0, 0])
score = np.array([0.9, 0.8, 0.6, 0.2, 0.7, 0.4, 0.3, 0.1])
for threshold in [0.3, 0.5, 0.8]:
    prediction = (score >= threshold).astype(int)
    # Rows are true classes; columns are predicted classes.
    confusion = np.bincount(2 * truth + prediction, minlength=4).reshape(2, 2)
    tn, fp, fn, tp = confusion.ravel()
    precision = tp / max(tp + fp, 1)
    recall = tp / max(tp + fn, 1)
    f1 = 2 * tp / max(2 * tp + fp + fn, 1)
    print(threshold, confusion.tolist(), precision, recall, f1)

dataset = TensorDataset(torch.tensor(normalized[train_idx], dtype=torch.float32))
loader = DataLoader(dataset, batch_size=7)
assert sum(len(batch[0]) for batch in loader) == len(train_idx)
```

The validation mean need not be zero; that fact may reveal a real distribution difference. Forcing it to zero using validation statistics would hide this particular observation.

The toy scores demonstrate threshold tradeoffs. They are not measurements of a trained model.

## 7. Uncertainty and reproducibility

A score from a small test set can vary considerably. Report sample counts, per-class support, and the independent evaluation unit. Repeating random seeds measures one source of variability; it does not fix a systematically leaky split.

For multiclass problems, macro averaging gives each class equal weight, while micro averaging aggregates decisions. State which is used. Inspect the confusion matrix rather than reporting a single number.
