## 1. Three different needs inside a visual network

After convolution, we may want to reduce spatial resolution, control activation scale, or make deep transformations easier to optimize. Pooling, normalization, and residual connections address these different needs.

They often appear together but are not interchangeable. Always inspect their effects on both values and shapes.

## 2. Pooling compresses a local region

For a patch containing $M$ values $x_1,\ldots,x_M$, average pooling returns their mean and max pooling returns their largest value:

$$
y_{\mathrm{avg}}=\frac{1}{M}\sum_jx_j,
\qquad
y_{\max}=\max_jx_j.
$$

For the patch $[1,3;2,0]$, the mean is $1.5$ and maximum is 3.

Pooling applies separately within each channel. A `2×2`, stride-2 pool usually halves each spatial dimension while keeping batch and channel axes unchanged.

Average pooling distributes an upstream derivative equally: $\partial y_{\mathrm{avg}}/\partial x_j=1/M$. Max pooling routes it to a selected maximizing entry; at ties the mathematical derivative is not unique and the implementation follows a particular choice.

For the patch $\begin{bmatrix}1&3\\2&0\end{bmatrix}$ and upstream scalar gradient 2, average pooling gives gradient $0.5$ at all four entries; max pooling gives 2 only at the entry containing 3. If pooling windows overlap, a pixel collects contributions from multiple windows.

Pooling discards information. A small important object can disappear during aggressive downsampling. Strided convolution is a learned alternative, not a guarantee against information loss.

## 3. Global average pooling creates a fixed-size representation

Suppose features have shape $(B,C,H,W)$. Average over spatial positions:

$$
s_{n,c}=\frac{1}{HW}\sum_{i,j}X_{n,c,i,j}.
$$

The result has shape $(B,C)$ independent of $H,W$. This connects a convolutional backbone to a linear classifier without a huge flattened layer.

Global averaging removes explicit position information. That is useful for many category tasks but insufficient for tasks requiring exact localization.

## 4. Normalization begins by choosing a group of values

For a chosen group $\mathcal S$ of $M$ entries, compute

$$
\mu=\frac{1}{M}\sum_{j\in\mathcal S}x_j,
\qquad
v=\frac{1}{M}\sum_{j\in\mathcal S}(x_j-\mu)^2.
$$

Subtracting $\mu$ centers the group. Dividing by $\sqrt{v+\varepsilon}$ rescales it, with $\varepsilon>0$ preventing division by zero. Learned scale $\gamma$ and shift $\beta$ allow the model to choose a useful output scale:

$$
y_j=\gamma_j\frac{x_j-\mu}{\sqrt{v+\varepsilon}}+\beta_j.
$$

The exact shapes of $\gamma,\beta$ depend on which normalization layer is used.

Normalization is differentiable through the statistics. The mean and variance depend on the input, so their derivatives are part of backpropagation.

### Why gradients must pass through the statistics

Treat one normalization group as a vector of length $M$. Write $c_j=x_j-\mu$, $r=\sqrt{v+\varepsilon}$, and $\widehat x_j=c_j/r$. Suppose the upstream output gradient is $g_{y,j}$ and define $u_j=\gamma_j g_{y,j}$.

First differentiate the scale denominator. Since $v=M^{-1}\sum_jc_j^2$ and $r^{-1}=(v+\varepsilon)^{-1/2}$,

$$
\frac{\partial L}{\partial v}
=-\frac{1}{2r^3}\sum_j u_jc_j.
$$

Each centered coordinate has a direct numerator path and an indirect variance path:

$$
g_{c,j}=\frac{u_j}{r}
+\frac{2c_j}{M}\frac{\partial L}{\partial v}.
$$

Finally, $c_j=x_j-M^{-1}\sum_kx_k$: changing one input changes **every** centered coordinate. Therefore

$$
g_{x,j}=g_{c,j}-\frac1M\sum_k g_{c,k}.
$$

Using $\sum_j c_j=0$, simplify the three steps to

$$
\boxed{
g_{x,j}
=\frac1r\left[
u_j-\operatorname{mean}(u)
-\widehat x_j\operatorname{mean}(u\odot\widehat x)
\right].
}
$$

The second and third terms are the corrections missing if mean and variance are incorrectly treated as constants. This formula includes $\varepsilon$ through $r$ and $\widehat{\mathbf{x}}$. For a single group, affine gradients are $g_{\gamma,j}=g_{y,j}\widehat x_j$ and $g_{\beta,j}=g_{y,j}$; sum contributions when affine parameters are shared across groups.

As a check, input gradients sum to zero within a group: adding a common constant to all inputs does not change normalized outputs. The companion script compares this manual LayerNorm backward and affine gradients to autograd in float64. The same groupwise principle applies to training-mode BatchNorm, with different grouping and parameter sharing.

## 5. BatchNorm and LayerNorm differ primarily in their axes

| Layer and input | Statistics computed over | Train/eval behavior |
|---|---|---|
| `BatchNorm2d(C)` on `(B,C,H,W)` | $(B,H,W)$ separately for each channel | Default: batch statistics in training, running estimates in eval |
| `LayerNorm(D)` on `(B,T,D)` | $D$ separately for each example and position | Uses the current input in both modes |
| `LayerNorm([C,H,W])` on `(B,C,H,W)` | $(C,H,W)$ separately for each example | Uses the current input in both modes |

For BatchNorm2d, learned scale and shift each have shape $(C,)$. Its default running estimates summarize training statistics and are not learned by gradient descent.

For LayerNorm, the specified trailing dimensions determine the normalization group and affine parameter shape. On an NCHW tensor, `LayerNorm(C)` tries to normalize the **width axis**, because that is the last axis. If $W=C$, it runs but still normalizes width, not channels. If $W\ne C$, it raises a shape error. To normalize channels per pixel, move channels to the trailing axis, normalize, then move them back; `LayerNorm([C,H,W])` instead normalizes all three trailing axes together.

PyTorch BatchNorm uses a biased variance for the current training normalization and an unbiased estimate when updating the running variance. The manual check below uses the training-forward convention. For running mean $\mu_{\mathrm{run}}$ and current batch mean $\mu_B$, PyTorch's usual update with parameter $m$ is

$$
\mu_{\mathrm{run,new}}=(1-m)\mu_{\mathrm{run,old}}+m\mu_B.
$$

With old mean 0, current batch mean 10, and $m=0.1$, the stored mean becomes 1, not 9. For more than one value per channel, running variance uses $v_{\mathrm{unbiased}}=M v_{\mathrm{biased}}/(M-1)$ in the analogous update. The forward training normalization still uses $v_{\mathrm{biased}}$.

In evaluation, default BatchNorm uses those **stored** statistics and does not update them; it does not recompute a separate normalization for the validation batch. With `track_running_stats=False`, however, it uses batch statistics in both modes. The initial manual experiment below chooses this flag only to isolate the formula; the companion script separately checks default-mode running statistics.

A framework's normalization “momentum” controls running-statistic updates; it is not optimizer momentum.

## 6. What normalization can and cannot do

Normalization often improves optimization behavior and controls scales, but it does not guarantee stable gradients or good generalization. Its benefit cannot be fully reduced to “making all activations Gaussian.”

BatchNorm estimates become more sensitive when the number of values per channel is small. A batch size of one with a large spatial map is different from one scalar per channel; after global pooling, a single training example may be insufficient for BatchNorm statistics.

Data-distribution changes can make running statistics inappropriate. LayerNorm avoids dependence on other examples in the batch, one reason it is useful for sequence models.

## 7. Residual connections provide an additive path

A plain block tries to learn a desired transformation $\mathcal H(\mathbf{x})$ directly. A residual block represents it as

$$
\mathbf{y}=\mathbf{x}+\mathcal F(\mathbf{x};\boldsymbol{\theta}).
$$

The branch learns a change relative to the input. Setting the branch near zero preserves information through the identity path.

Differentiate one output coordinate first: $y_i=x_i+\mathcal F_i(\mathbf{x})$ gives $\partial y_i/\partial x_j=\delta_{ij}+\partial\mathcal F_i/\partial x_j$, where $\delta_{ij}$ is 1 only when $i=j$. Stack these partial derivatives to obtain $\mathbf{J}_{\mathbf{y}}=\mathbf{I}+\mathbf{J}_{\mathcal F}$.

For an upstream gradient $\mathbf{g}_y$ and branch Jacobian $\mathbf{J}_{\mathcal F}$,

$$
\mathbf{g}_x
=(\mathbf{I}+\mathbf{J}_{\mathcal F})^{\mathsf T}\mathbf{g}_y
=\mathbf{g}_y+\mathbf{J}_{\mathcal F}^{\mathsf T}\mathbf{g}_y.
$$

The direct term adds a path that does not traverse the branch's entire sequence of operations. It helps optimization, but terms can still cancel and gradients can still grow or vanish.

Addition requires matching shapes. If channels or resolution change, use a learned projection $\mathcal P(\mathbf{x})$ so that $\mathbf{y}=\mathcal P(\mathbf{x})+\mathcal F(\mathbf{x})$. The direct path is then a projection rather than the identity.

## 8. Runnable experiment: pooling, normalization, and the direct gradient

```python
import torch
import torch.nn.functional as F
from torch import nn

torch.manual_seed(1)
x = torch.tensor([[[[1., 3.], [2., 0.]]]], requires_grad=True)
maximum = F.max_pool2d(x, 2)
maximum.sum().backward()
torch.testing.assert_close(x.grad, torch.tensor([[[[0., 1.], [0., 0.]]]]))
average = F.avg_pool2d(x.detach(), 2)
torch.testing.assert_close(average, torch.tensor([[1.5]]))

features = torch.randn(4, 3, 5, 5)
bn = nn.BatchNorm2d(3, affine=False, track_running_stats=False)
mean = features.mean(dim=(0, 2, 3), keepdim=True)
var = features.var(dim=(0, 2, 3), unbiased=False, keepdim=True)
manual_bn = (features - mean) / torch.sqrt(var + bn.eps)
torch.testing.assert_close(bn(features), manual_bn, atol=1e-6, rtol=1e-5)

sequence = torch.randn(2, 4, 6)
ln = nn.LayerNorm(6, elementwise_affine=False)
mu = sequence.mean(-1, keepdim=True)
variance = sequence.var(-1, unbiased=False, keepdim=True)
torch.testing.assert_close(ln(sequence), (sequence - mu) / (variance + ln.eps).sqrt())

branch = nn.Linear(3, 3, bias=False)
with torch.no_grad():
    branch.weight.zero_()
inputs = torch.randn(2, 3, requires_grad=True)
outputs = inputs + branch(inputs)
outputs.sum().backward()
torch.testing.assert_close(inputs.grad, torch.ones_like(inputs))
torch.testing.assert_close(outputs, inputs)
print("pooling, normalization, and residual checks passed")
```

The residual check deliberately uses a zero branch to isolate the identity path. The companion script also checks a cancellation counterexample: `outputs = inputs - inputs` has zero input gradient despite containing an identity summand. It checks training-mode BatchNorm batch dependence, evaluation-mode independence with frozen statistics, and LayerNorm's per-example independence. A real nonlinear block can add additional activation effects, including an activation after the addition.
