## 1. Motivation: adding depth should make useful transformations available

A deep network can build hierarchical features: local edges, combinations of edges, and larger patterns. But simply adding layers can make optimization harder. Even training error can become worse; that is an optimization issue, not automatically overfitting.

If extra layers could easily preserve their inputs, a deeper model could at least represent the shallower computation. Residual blocks make this preservation explicit and learn changes around it.

This does not prove every deeper network will train better. It creates a useful parameterization that must still be tested.

## 2. A basic residual block

Consider a block with two $3\times3$ convolutions. Its branch computes a sequence of convolution, normalization, activation, convolution, and normalization. The shortcut then adds the input or a projected input.

For a post-activation version,

$$
\mathbf{z}=\mathcal F(\mathbf{x}),
\qquad
\mathbf{y}=\operatorname{ReLU}\bigl(\mathbf{z}+\mathcal P(\mathbf{x})\bigr).
$$

When dimensions match, $\mathcal P$ is the identity. If channels change from $C_{\mathrm{in}}$ to $C_{\mathrm{out}}$ or stride is 2, a $1\times1$ convolution with the same stride makes the shortcut compatible.

The final ReLU matters: the full post-activation block is not an unrestricted identity map for negative inputs even when the branch is zero. Pre-activation designs place normalization and activations differently; “ResNet” describes a family of architectures.

## 3. Track the network stage by stage

For a batch of grayscale $32\times32$ images, our small network uses:

| Stage | Output shape | Reason |
|---|---|---|
| Input | $(B,1,32,32)$ | One image channel |
| Stem convolution | $(B,8,32,32)$ | Stride 1, padding 1 |
| Residual stage 1 | $(B,8,32,32)$ | Same resolution and channels |
| Residual stage 2 | $(B,16,16,16)$ | First convolution and shortcut use stride 2 |
| Global average pool | $(B,16,1,1)$ | Average spatial dimensions |
| Flatten and classifier | $(B,K)$ | One logit per class |

For the stride-2 block with input $(B,8,32,32)$, the first $3\times3$ branch convolution uses padding 1 and produces spatial size $\lfloor(32+2-3)/2\rfloor+1=16$. The shortcut's $1\times1$ convolution uses padding 0 and also produces $\lfloor(32-1)/2\rfloor+1=16$. Both project to 16 channels, so both arrive at $(B,16,16,16)$.

A $1\times1$ convolution mixes channels at each location. With stride 2 it also subsamples spatially. It is not the same operation as pooling, because channel mixing is learned.

## 4. Why initialization still matters

For ReLU convolutional branches, Kaiming initialization chooses a scale intended to avoid severe signal shrinkage at the start. BatchNorm begins with scale 1 and shift 0 by default.

An optional residual initialization sets the final normalization scale in each branch to zero, so the branch initially contributes zero. This favors identity-like behavior on matching shortcuts. It is a design choice, not a requirement for all models.

Why is zeroing the branch's final scale different from zeroing every weight? If the last BatchNorm output is $\boldsymbol{\gamma}\odot\widehat{\mathbf{z}}+\boldsymbol{\beta}$ with $\boldsymbol{\gamma}=\boldsymbol{\beta}=\mathbf{0}$, the branch initially outputs zero. Yet the gradient of $\gamma_j$ contains $\widehat z_j$, which can be nonzero because earlier convolutions are randomly initialized. The scale can learn to open that branch; initially, its zero scale blocks gradients into earlier branch weights.

Avoid zero-initializing every weight in an ordinary multilayer network: symmetry can prevent neurons from learning distinct features.

## 5. Runnable implementation and gradient check

This is a deliberately small teaching network, not a claim to reproduce a particular published ResNet exactly.

```python
import torch
from torch import nn

torch.manual_seed(12)
torch.set_num_threads(1)

class BasicBlock(nn.Module):
    def __init__(self, in_channels, out_channels, stride=1):
        super().__init__()
        self.conv1 = nn.Conv2d(in_channels, out_channels, 3,
                               stride=stride, padding=1, bias=False)
        self.bn1 = nn.BatchNorm2d(out_channels)
        self.conv2 = nn.Conv2d(out_channels, out_channels, 3,
                               padding=1, bias=False)
        self.bn2 = nn.BatchNorm2d(out_channels)
        self.activation = nn.ReLU()
        if stride != 1 or in_channels != out_channels:
            self.shortcut = nn.Sequential(
                nn.Conv2d(in_channels, out_channels, 1, stride=stride, bias=False),
                nn.BatchNorm2d(out_channels),
            )
        else:
            self.shortcut = nn.Identity()

    def forward(self, x):
        identity = self.shortcut(x)
        z = self.activation(self.bn1(self.conv1(x)))
        z = self.bn2(self.conv2(z))
        assert z.shape == identity.shape
        return self.activation(z + identity)

class TinyResNet(nn.Module):
    def __init__(self, classes=3):
        super().__init__()
        self.backbone = nn.Sequential(
            nn.Conv2d(1, 8, 3, padding=1, bias=False),
            nn.BatchNorm2d(8),
            nn.ReLU(),
            BasicBlock(8, 8),
            BasicBlock(8, 16, stride=2),
            nn.AdaptiveAvgPool2d(1),
            nn.Flatten(),
        )
        self.head = nn.Linear(16, classes)
        for module in self.modules():
            if isinstance(module, nn.Conv2d):
                nn.init.kaiming_normal_(module.weight, mode="fan_out",
                                        nonlinearity="relu")

    def forward(self, x):
        return self.head(self.backbone(x))

model = TinyResNet()
images = torch.randn(4, 1, 32, 32)
labels = torch.tensor([0, 1, 2, 0])
logits = model(images)
assert logits.shape == (4, 3)
loss = nn.CrossEntropyLoss()(logits, labels)
loss.backward()
assert all(p.grad is not None for p in model.parameters())
assert all(torch.isfinite(p.grad).all() for p in model.parameters())

# Freeze the backbone for a head-only training step.
for parameter in model.backbone.parameters():
    parameter.requires_grad_(False)
model.zero_grad(set_to_none=True)
model.train()
model.backbone.eval()  # Keep frozen BatchNorm running statistics fixed too.
optimizer = torch.optim.SGD(model.head.parameters(), lr=0.1)
backbone_before = {k:v.clone() for k,v in model.backbone.state_dict().items()}
head_before = {k:v.clone() for k,v in model.head.state_dict().items()}
optimizer.zero_grad(set_to_none=True)
nn.CrossEntropyLoss()(model(images), labels).backward()
optimizer.step()
assert all(p.grad is None for p in model.backbone.parameters())
for key,value in model.backbone.state_dict().items():
    torch.testing.assert_close(value,backbone_before[key],atol=0,rtol=0)
assert any(not torch.equal(value,head_before[key]) for key,value in model.head.state_dict().items())
print("logits:", logits.shape, "parameters:", sum(p.numel() for p in model.parameters()))


# Freezing parameters alone does not freeze running statistics.
unfrozen_stats = nn.BatchNorm2d(3)
for parameter in unfrozen_stats.parameters():
    parameter.requires_grad_(False)
before = unfrozen_stats.running_mean.clone()
unfrozen_stats.train()
unfrozen_stats(torch.full((2,3,2,2),5.))
assert not torch.equal(unfrozen_stats.running_mean,before)
assert all(parameter.grad is None for parameter in unfrozen_stats.parameters())
print("backbone values/buffers frozen, head changed, BN negative control verified")
```

Freezing should be verified with values, not only with `grad is None`. The companion script snapshots the complete backbone state (parameters **and** BatchNorm buffers), performs the head-only step, and checks that the backbone is unchanged while at least one head parameter changed. A negative control leaves a parameter-frozen BatchNorm module in training mode and confirms its running mean can still change.

The frozen example demonstrates the mechanics on a random network. Useful transfer learning normally begins with weights trained on a relevant source task.

## 6. Transfer learning as reuse of a representation

A pretrained backbone has already learned features from a source dataset. For a new task:

1. Match preprocessing to the pretrained model: channel order, range, normalization, and resolution.
2. Replace its classification head to match the new classes.
3. Establish a head-only baseline with the backbone frozen.
4. Optionally unfreeze later stages or the whole model with a carefully chosen rate.
5. Select based on held-out results.

Freezing parameters disables their gradients but does not automatically freeze BatchNorm running statistics. Set the appropriate module mode deliberately. Conversely, `eval()` alone does not freeze parameter gradients.

When unfreezing, ensure the optimizer includes the newly trainable parameters. If the original optimizer only contained the head, flipping `requires_grad` on the backbone is insufficient.

## 7. Data augmentation and visual task assumptions

Small translations or crops may be reasonable for object categories. Cropping must preserve enough evidence for the assigned label. Flips can change a left/right distinction or text; rotations change orientation labels.

Use the source model's expected preprocessing when reusing weights. A strong pretrained model with the wrong input normalization can perform poorly for a mundane reason.
