## 1. Motivation: images contain repeated local patterns

An RGB image of size $224\times224$ contains 150,528 values. Connecting every pixel to 1,000 hidden neurons needs over 150 million weights. A fully connected layer can learn spatial patterns, but it does not explicitly reuse a detector across image positions.

A small edge pattern can appear anywhere. Convolution encodes two useful assumptions: nearby pixels are related, and the same local pattern may matter at many locations. It uses **local connectivity** and **shared weights**.

These are inductive biases, not universal properties of every task.

## 2. One local detector, one input channel

Start with a grayscale image $\mathbf{X}\in\mathbb{R}^{H\times W}$ and a kernel $\mathbf{K}\in\mathbb{R}^{k_H\times k_W}$. At position $(i,j)$, multiply the local patch and kernel entry by entry, then add the products:

$$
Y_{ij}
=\sum_{u=0}^{k_H-1}\sum_{v=0}^{k_W-1}
K_{uv}X_{i+u,j+v}+b.
$$

The result is one scalar response for that patch. Shift the patch and repeat with **the same** kernel values. A kernel does not have to be hand-designed; backpropagation learns its entries.

For

$$
\mathbf{X}=
\begin{bmatrix}
1&2&3\\4&5&6\\7&8&9
\end{bmatrix},
\quad
\mathbf{K}=
\begin{bmatrix}
1&0\\0&-1
\end{bmatrix},
$$

the upper-left response is $1-5=-4$. Sliding across all valid positions yields a $2\times2$ output containing -4 in every position.

Deep learning libraries usually implement **cross-correlation**, meaning the kernel is not flipped. Mathematical convolution flips its spatial axes. The conventional layer name is still “convolution.”

## 3. Channels: combine several input maps into each output map

An RGB input has three channels. One output detector uses a separate spatial kernel for each input channel and **sums** their responses.

For a batch $\mathbf{X}\in\mathbb{R}^{B\times C_{\mathrm{in}}\times H\times W}$, use weights

$$
\mathbf{W}\in
\mathbb{R}^{C_{\mathrm{out}}\times C_{\mathrm{in}}\times k_H\times k_W}.
$$

There is one bias per output channel. For stride 1 without padding,

$$
Y_{n,o,i,j}
=b_o+
\sum_{c=0}^{C_{\mathrm{in}}-1}
\sum_{u=0}^{k_H-1}
\sum_{v=0}^{k_W-1}
W_{o,c,u,v}X_{n,c,i+u,j+v}.
$$

Here $n$ indexes examples, $o$ output channels, and $c$ input channels. The sum removes $c,u,v$, leaving axes $(n,o,i,j)$.

For an ordinary convolution with `groups=1`, the parameter count is

$$
C_{\mathrm{out}}C_{\mathrm{in}}k_Hk_W+C_{\mathrm{out}}.
$$

It does not depend on image height or width. Increasing image resolution increases computation and activation storage, not the number of convolution weights.

## 4. Derive the output size instead of memorizing it

Consider one spatial dimension of input length $H$. Padding $p$ on each side gives length $H+2p$. With dilation $d$, a kernel containing $k$ entries spans an effective length

$$
k_{\mathrm{eff}}=d(k-1)+1.
$$

For example, three entries spaced two pixels apart cover positions 0, 2, and 4: effective length 5.

A window's starting point must lie between 0 and $H+2p-k_{\mathrm{eff}}$. With stride $s$, valid starts are $0,s,2s,\ldots$. Counting them gives

$$
H_{\mathrm{out}}
=\left\lfloor\frac{H+2p-d(k-1)-1}{s}\right\rfloor+1.
$$

Width follows the same derivation. Assume the padded input is large enough for at least one window.

For $H=7$, $k=3$, $p=1$, $s=2$, and $d=1$, the padded length is 9, window starts are 0, 2, 4, and 6, so $H_{\mathrm{out}}=4$.

“Same size” for an odd kernel with stride 1 and dilation 1 uses $p=(k-1)/2$. Other strides or even kernels need more care, potentially asymmetric padding.

## 5. Receptive fields grow through layers

A receptive field describes which input locations can affect one activation. Let $r_l$ be receptive-field width after layer $l$ and $j_l$ the spacing in input pixels between neighboring layer-$l$ activations.

Initially $r_0=1$ and $j_0=1$. A layer adds $(k_{\mathrm{eff},l}-1)$ gaps measured in the previous spacing:

$$
r_l=r_{l-1}+(k_{\mathrm{eff},l}-1)j_{l-1},
\qquad
j_l=j_{l-1}s_l.
$$

Two $3\times3$, stride-1 convolutions give receptive-field width 5. If the first has stride 2, its spacing becomes 2, and the second produces width $3+2\cdot2=7$.

This is the theoretical receptive field. Learned weights may make some input locations contribute much less than others.

## 6. How a shared weight learns from every position

A kernel entry influences many output positions. The chain rule adds all those contributions.

If $G_{n,o,i,j}=\partial L/\partial Y_{n,o,i,j}$ is the upstream gradient, then for stride 1 without padding,

$$
\frac{\partial L}{\partial W_{o,c,u,v}}
=\sum_{n,i,j}G_{n,o,i,j}X_{n,c,i+u,j+v}.
$$

Why sum these products? Fix one weight $W_{o,c,u,v}$. Its local derivative at output $(n,o,i,j)$ is the input value $X_{n,c,i+u,j+v}$. Multiply by that output's loss sensitivity, then add over every use of the same weight. This is the same principle as an MLP weight gradient, with an extra sum over spatial positions.

In the $3\times3$ example, let $L=\sum_{i,j}Y_{ij}$ so all upstream entries are 1. The top-left weight sees inputs $1,2,4,5$, giving derivative 12. Repeating for the other offsets gives

$$
\nabla_{\mathbf{K}}L
=\begin{bmatrix}12&16\\24&28\end{bmatrix}.
$$

Input gradients work in reverse: each output adds its upstream gradient times the kernel into its input patch. Overlapping patches add their contributions. For this kernel and all-ones upstream gradient,

$$
\nabla_{\mathbf{X}}L
=\begin{bmatrix}1&1&0\\1&0&-1\\0&-1&-1\end{bmatrix}.
$$

The center receives $+1$ from one window and $-1$ from another, which cancel. A zero input gradient need not mean the pixel was unused.

The companion script checks both input and kernel gradients with nonuniform upstream values, plus a kernel entry by central differences. It also checks a batched, multi-channel convolution to verify the sum over input channels.

## 7. Runnable experiment: implement correlation and check autograd

```python
import numpy as np
import torch
import torch.nn.functional as F

def correlate2d(image, kernel, padding=0, stride=1, dilation=1):
    padded = np.pad(image, ((padding, padding), (padding, padding)))
    kh, kw = kernel.shape
    eh, ew = dilation * (kh - 1) + 1, dilation * (kw - 1) + 1
    oh = (padded.shape[0] - eh) // stride + 1
    ow = (padded.shape[1] - ew) // stride + 1
    output = np.empty((oh, ow), dtype=np.float64)
    for i in range(oh):
        for j in range(ow):
            patch = padded[i*stride:i*stride+eh:dilation,
                           j*stride:j*stride+ew:dilation]
            output[i, j] = (patch * kernel).sum()
    return output

image = np.arange(1., 10.).reshape(3, 3)
kernel = np.array([[1., 0.], [0., -1.]])
manual = correlate2d(image, kernel)
x = torch.tensor(image)[None, None]
w = torch.tensor(kernel)[None, None].requires_grad_()
actual = F.conv2d(x, w)
np.testing.assert_allclose(actual.detach().numpy()[0, 0], manual)
np.testing.assert_allclose(manual, np.full((2, 2), -4.))

actual.sum().backward()  # All upstream entries are 1.
expected_dw = np.zeros_like(kernel)
for i in range(2):
    for j in range(2):
        expected_dw += image[i:i+2, j:j+2]
np.testing.assert_allclose(w.grad.numpy()[0, 0], expected_dw)

rng = np.random.default_rng(9)
image2 = rng.normal(size=(7, 7))
kernel2 = rng.normal(size=(3, 3))
for padding, stride, dilation in [(1, 2, 1), (2, 1, 2)]:
    manual2 = correlate2d(image2, kernel2, padding, stride, dilation)
    result = F.conv2d(torch.tensor(image2)[None, None],
                      torch.tensor(kernel2)[None, None],
                      padding=padding, stride=stride, dilation=dilation)
    np.testing.assert_allclose(result.numpy()[0, 0], manual2, atol=1e-12)
    print("output shape:", result.shape)

layer = torch.nn.Conv2d(3, 8, kernel_size=3, padding=1)
print("weight:", layer.weight.shape)
assert sum(p.numel() for p in layer.parameters()) == 8 * 3 * 3 * 3 + 8
```

## 8. Translation and limits

With stride 1 away from boundaries, shifting an input shifts its convolution responses. This is **translation equivariance**, not invariance. Padding boundaries, stride, pooling, and the final classifier affect this property.

A classification head can aggregate positions to reduce sensitivity to location. It may also discard useful location information. Choose the architecture according to the task.
