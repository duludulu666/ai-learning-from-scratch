## 1. Motivation: identifiers are not meaningful measurements

A vocabulary assigns an integer ID to each symbol. If “cat” has ID 17 and “dog” ID 18, subtracting the IDs does not establish semantic similarity. The numbering is arbitrary.

We want a trainable vector associated with each symbol. An **embedding table** contains these vectors, and an ID selects one row. Training adjusts the selected rows according to the task loss.

## 2. Derive lookup from a one-hot linear map

Let vocabulary size be $V$ and embedding dimension be $D$. Define

$$
\mathbf{E}\in\mathbb{R}^{V\times D}.
$$

Row $\mathbf{E}_{k,:}$ is the vector for ID $k$. Let $\mathbf{o}_k\in\mathbb{R}^{V}$ be a one-hot column vector: entry $k$ is 1 and other entries are 0.

Multiplying by the table selects the row:

$$
\mathbf{e}_k=\mathbf{E}^{\mathsf T}\mathbf{o}_k\in\mathbb{R}^{D}.
$$

In batched row notation, one-hot rows $\mathbf{O}\in\mathbb{R}^{N\times V}$ give $\mathbf{Z}=\mathbf{O}\mathbf{E}$.

An embedding lookup computes this selection without allocating a large one-hot array. The integer ID is an index; gradients flow to table entries, not to the discrete ID.

## 3. Shapes for a sequence

For token IDs with shape $(B,T)$, `nn.Embedding(V,D)` returns $(B,T,D)$. Each position receives a vector of length $D$.

The table has $VD$ scalar parameters regardless of batch size and sequence length. Increasing vocabulary size increases the table; processing longer sequences increases activation memory and computation.

A static embedding table gives the same vector whenever the same ID appears. An RNN or Transformer transforms those vectors into **contextual representations**, which can differ between occurrences of the same word.

## 4. Derive why repeated IDs accumulate gradients

Suppose positions $n$ select IDs $k_n$, and their output gradients are $\mathbf{g}_n=\partial L/\partial\mathbf{e}_{k_n}$. A table row may be reused at several positions.

By the chain rule,

$$
\frac{\partial L}{\partial\mathbf{E}_{k,:}}
=\sum_{n:k_n=k}\mathbf{g}_n^{\mathsf T}.
$$

Rows never used by a plain lookup have zero data gradient for that step. Weight decay or additional uses of the table can still change their values. A tied output classifier, for example, can involve all vocabulary rows.

For IDs $[1,1,4]$ and upstream rows $[(1,2),(3,-1),(-2,4)]$, row 1 receives $(1,2)+(3,-1)=(4,1)$, row 4 receives $(-2,4)$, and unused rows receive zero lookup gradient. The companion script checks this nonuniform example as well as the all-ones example below.

This is the same shared-parameter principle seen in convolution and recurrent networks.

## 5. Padding is a separate concern

A padding ID marks positions inserted for batching. With `padding_idx=0`, PyTorch initializes that embedding row to zero and suppresses its lookup gradient.

A zero padding vector still changes an **unmasked** mean: embeddings $(2,4)$ and $(4,2)$ average to $(3,3)$, but appending two zero vectors and dividing by four gives $(1.5,1.5)$. Zero is not the same as “exclude this position from the denominator.”

That does not automatically mask a pooled mean, an RNN state update, an attention computation, or the loss. For mean pooling, count only real positions:

$$
\bar{\mathbf{e}}_n
=\frac{\sum_t m_{n,t}\mathbf{e}_{n,t}}
       {\max(1,\sum_t m_{n,t})}.
$$

Here $m_{n,t}=1$ for valid tokens. If no token is valid, the displayed convention returns a zero summary, but you should decide explicitly whether an empty input is valid for your task. A biased classifier applied to that zero summary still returns its learned bias logits, not a meaningful prediction from evidence. The companion script tests padding-extension invariance, arbitrary finite PAD-row contents under explicit masking, and the empty-input convention.

## 6. Similarity depends on the learned task

An inner product $\mathbf{u}^{\mathsf T}\mathbf{v}$ depends on vector magnitude and direction. Cosine similarity normalizes magnitude:

$$
\operatorname{cos}(\mathbf{u},\mathbf{v})
=\frac{\mathbf{u}^{\mathsf T}\mathbf{v}}
{\|\mathbf{u}\|_2\|\mathbf{v}\|_2}.
$$

For a zero vector this expression is undefined; implementations need a numerical convention.

Nearby vectors may reflect useful relationships if the objective rewards them. Random embeddings contain no learned semantics. A classifier trained only to distinguish positive and negative sentiment is not guaranteed to organize geography, syntax, or every other relation meaningfully.

Embedding coordinates are also not uniquely interpretable. For a row representation $\mathbf{e}$ followed by linear map $\mathbf{A}$, choose an invertible matrix $\mathbf{R}$ and replace $\mathbf{e}$ by $\mathbf{e}\mathbf{R}$ and $\mathbf{A}$ by $\mathbf{R}^{-1}\mathbf{A}$. Then $(\mathbf{e}\mathbf{R})(\mathbf{R}^{-1}\mathbf{A})=\mathbf{e}\mathbf{A}$. Outputs stay identical while the coordinates change. Orthogonal changes preserve dot products and cosine similarities; general invertible changes need not. Extra constraints such as weight tying, normalization, or regularization can restrict this freedom.

## 7. Runnable experiment: lookup equivalence and repeated-row gradients

```python
import torch
import torch.nn.functional as F
from torch import nn

torch.manual_seed(14)
V, D = 6, 3
embedding = nn.Embedding(V, D).double()
ids = torch.tensor([1, 1, 4])
lookup = embedding(ids)
one_hot = F.one_hot(ids, num_classes=V).double()
torch.testing.assert_close(lookup, one_hot @ embedding.weight)

lookup.sum().backward()
expected = torch.zeros(V, D, dtype=torch.float64)
expected[1] = 2.0
expected[4] = 1.0
torch.testing.assert_close(embedding.weight.grad, expected)

padded_embedding = nn.Embedding(V, D, padding_idx=0)
batch_ids = torch.tensor([[1, 2, 0], [4, 0, 0]])
mask = batch_ids.ne(0)
vectors = padded_embedding(batch_ids)
summary = (vectors * mask[..., None]).sum(1) / mask.sum(1, keepdim=True).clamp_min(1)
torch.testing.assert_close(summary[1], padded_embedding.weight[4])
summary.sum().backward()
torch.testing.assert_close(padded_embedding.weight.grad[0], torch.zeros(D))
print("embedding output:", vectors.shape)
print("repeated-token row gradient:", embedding.weight.grad[1])
```

## 8. Runnable learned representation: a tiny unordered token classifier

This experiment learns an embedding table from labels and uses a masked mean. Its deliberate limitation is that it cannot distinguish token order.

```python
import torch
import torch.nn.functional as F
from torch import nn

torch.manual_seed(15)
torch.set_num_threads(1)
ids = torch.tensor([
    [1, 2, 0], [2, 1, 0], [1, 1, 2], [2, 2, 0],
    [3, 4, 0], [4, 3, 0], [3, 3, 4], [4, 4, 0],
])
labels = torch.tensor([0, 0, 0, 0, 1, 1, 1, 1])

class TokenClassifier(nn.Module):
    def __init__(self):
        super().__init__()
        self.embedding = nn.Embedding(5, 4, padding_idx=0)
        self.head = nn.Linear(4, 2)

    def forward(self, tokens):
        valid = tokens.ne(0)
        vectors = self.embedding(tokens)
        pooled = (vectors * valid[..., None]).sum(1)
        pooled = pooled / valid.sum(1, keepdim=True).clamp_min(1)
        return self.head(pooled)

model = TokenClassifier()
optimizer = torch.optim.SGD(model.parameters(), lr=0.2)
for _ in range(120):
    optimizer.zero_grad(set_to_none=True)
    loss = F.cross_entropy(model(ids), labels)
    loss.backward()
    optimizer.step()

model.eval()
with torch.no_grad():
    print("training accuracy:", model(ids).argmax(-1).eq(labels).float().mean().item())
    first = model(torch.tensor(1, 2, 0))
    reordered = model(torch.tensor(2, 1, 0))
    torch.testing.assert_close(first, reordered)
```

High accuracy here means the model fits this tiny supplied pattern. It does not establish broad language understanding. The invariance check proves that mean pooling loses order, regardless of training success.

## 9. Bridge to Attention and Transformer

An RNN reads embeddings through a sequential state. Its path between distant positions can be long, and hidden-state updates are sequential.

Attention will let a position directly combine information from other positions using data-dependent weights. Embeddings supply the vectors; attention provides contextual interaction. Position information remains necessary because a collection of token vectors alone does not define order.

The next part begins with the problem of selecting relevant information, then derives Query, Key, Value, and scaled dot-product attention. No large-model APIs are needed to understand that mechanism.
