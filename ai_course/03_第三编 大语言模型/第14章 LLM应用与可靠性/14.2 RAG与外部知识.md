## 1. Why put knowledge outside the parameters?

A language model's weights do not automatically reflect a newly updated policy or a private document it has never seen. Retraining for every fact is often impractical.

Retrieval-Augmented Generation (RAG) retrieves relevant external evidence and supplies it as context when answering. It changes the information available at inference, not necessarily the model weights.

RAG can fail because the right evidence was not indexed, retrieval missed it, context construction dropped it, the model misread it or the source itself was wrong. A citation alone does not distinguish these failures.

## 2. Define the pipeline before choosing an embedding model

A typical pipeline is:

```text
authorized documents → chunks + metadata → index
question → retrieval → optional reranking → bounded context
        → answer generation → citations + support checks
```

Preserve document IDs, source/version, permissions and chunk offsets. Chunking should keep useful semantic units without exceeding context budget. Overlap can preserve continuity but also creates duplicate retrieval hits.

Access control should restrict the searchable candidate set before sensitive text reaches the model. Filtering only after answer generation is too late. In a shared index, validate the retrieval system's metadata-filter semantics.

Our lab constructs a guest-only index from four fabricated public policies. A fifth staff-only policy is excluded. No personal Obsidian notes are ingested.

## 3. Start with an interpretable lexical baseline

Before dense embeddings, implement a simple TF-IDF cosine retriever.

Let $c_{t,d}$ count term $t$ in document $d$, $n$ be document count, and $\mathrm{df}_t$ count documents containing $t$. Our smoothed inverse-document-frequency weight is

$$
\mathrm{idf}_t=\log\frac{1+n}{1+\mathrm{df}_t}+1.
$$

For four documents, a term appearing in one has IDF $\log(5/2)+1\approx1.916$, while a term appearing in all four has IDF 1. Rare terms receive more weight under this convention.

Represent the document with coordinates $v_{t,d}=c_{t,d}\mathrm{idf}_t$. Apply the same IDF table to query term counts, giving vector $\mathbf q$.

Cosine similarity is

$$
\mathrm{sim}(\mathbf q,\mathbf v_d)
=\frac{\mathbf q^{\mathsf T}\mathbf v_d}
{\|\mathbf q\|_2\|\mathbf v_d\|_2}.
$$

Terms absent from the index vocabulary are ignored. An all-unknown query has zero vector norm; return no hits rather than divide by zero.

The lab uses word counts, not a production BM25 implementation. IDF values and tokenization are part of the retrieval specification.

## 4. What dense retrieval adds

A learned encoder maps queries and documents to vectors intended to place related meanings near each other. Cosine or dot-product search can then retrieve paraphrases without exact word overlap.

The two encoders, normalization and similarity convention must be compatible. Raw cosine is not a calibrated probability of relevance. Dot product also depends on vector magnitude: for $\mathbf q=[1,0]$, document vectors $[1,0]$ and $[100,1]$ have dot products 1 and 100, while cosine scores are 1 and approximately 0.99995. Normalization changes ranking behavior, not just formatting. Domain shift can make a sophisticated embedding model worse than a strong lexical baseline.

Hybrid retrieval combines lexical and dense candidates. Reranking can score the question and candidate text jointly, often at greater cost. A reranker cannot recover a document absent from its candidate set.

Our offline lab does **not** download a semantic embedding model. It compares a TF-IDF baseline with a tiny explicit synonym map such as `borrow → loans`. This isolates the mismatch problem but is not evidence of learned semantic retrieval.

## 5. Work a small retrieval example

The public corpus includes “Library book loans last 14 days.” A query containing `book loans` overlaps directly. The query `borrow` has no lexical match in the baseline.

After applying the documented synonym map to both indexed text and query, `borrow` maps to `loans` and becomes retrievable. This is a hand-designed rule on a tiny fixture, not an independent benchmark improvement.

The private record says staff loans last 60 days. Even if its words match better, a guest must never receive it. Relevance ranking and authorization answer different questions.

## 6. Evaluate retrieval before generation

Let $G_q$ be the set of known relevant document IDs for question $q$ and $R_q^{(k)}$ the top-$k$ retrieved IDs. Recall is

$$
\mathrm{Recall@}k
=\frac{|G_q\cap R_q^{(k)}|}{|G_q|}.
$$

With one relevant item per query, this is simply whether it appears. Reciprocal rank is $1/r_q$ for the first relevant rank $r_q$, or zero if none is retrieved. Average over queries for MRR.

Questions with no relevant document need separate abstention metrics; their recall denominator is zero and should not be silently treated as ordinary answerable queries.

The lab reports recall@1, recall@3 and MRR over six authored questions. Two paraphrase questions expose the lexical mismatch. The same fixture informed the synonym design, so the scores are development checks, not held-out generalization estimates.

If relevant IDs are $\{a,b\}$ and the returned top two are $[c,b]$, recall@2 is $1/2$, precision@2 is $1/2$, and reciprocal rank is $1/2$. With three relevant documents and one found at rank 1, recall@1 is $1/3$ but reciprocal rank is 1. They measure different things.

For answerable and unanswerable questions, also track answer coverage and error **among answered cases**. Always abstaining can eliminate wrong answers while providing no useful coverage. Choose thresholds on development data, freeze them, then evaluate held-out questions.

## 7. Grounding is another stage

After retrieval, a generator might still answer “999 days” while citing the correct loans document. Citation existence is not entailment.

Our demonstration uses a deterministic extractor returning a stored answer field, not an LLM. An exact expected-answer checker verifies support only for these fabricated policies. It cannot judge arbitrary prose.

The original `extractive_answer` ignores question meaning once a retrieval threshold passes. For `book loans quantum superconductivity`, the unknown words drop out of TF-IDF, the loans document scores well, and the naive extractor answers “14 days.” A valid citation and a fact present in a document still fail to establish that the answer addresses the question.

We retain this as a **negative control**. The new `guarded_fixture_answer` accepts only a documented registry of known question intents and their expected source IDs; it abstains on the adversarial example. This is intentionally narrow and rejects unseen paraphrases. It demonstrates separating answerability from retrieval similarity, not a general semantic solution. A real system needs a validated answerability/support mechanism and held-out unknown questions.

For a real RAG system, separately evaluate answer correctness, claim-to-source support, citation precision, refusal on missing evidence and robustness to conflicting or outdated sources. A model judge needs calibration against human labels and can have position or verbosity bias.

## 8. Context construction and injection

Limit context size, remove redundant chunks, preserve source IDs and label document text as untrusted evidence.

For context accounting, let $T_{\mathrm{max}}$ be an application total-token allowance, $T_{\mathrm{fixed}}$ fixed prompt/query overhead, and $T_{\mathrm{output}}$ the reserved generation allowance. The evidence budget is

$$
T_{\mathrm{evidence}}\le T_{\mathrm{max}}-T_{\mathrm{fixed}}-T_{\mathrm{output}}.
$$

With 1,000 available tokens, 200 overhead and 150 reserved for output, at most 650 remain. Three 300-token chunks do not all fit; add citation headers and serialization overhead before packing. Actual serving limits differ, so this is a budgeting convention rather than a vendor limit. Truncating away the sentence supporting a citation breaks grounding even if the source ID survives. Rank order and truncation affect what the generator sees.

A retrieved page can contain instructions to reveal secrets or call tools. Do not promote it into developer/system instructions or treat its claimed permissions as authoritative. A generated citation list must be checked against authorized supplied sources.

RAG introduces external information; it does not automatically make that information trustworthy or eliminate hallucination.

## 9. Minimal cosine check and full lab

```python
import math
q = [1.,1.,0.]
d = [1.,0.,1.]
cosine = sum(a*b for a,b in zip(q,d)) / (
    math.sqrt(sum(a*a for a in q))*math.sqrt(sum(b*b for b in d)))
assert math.isclose(cosine,.5)
print("cosine:",cosine)
```
