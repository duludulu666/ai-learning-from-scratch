# 12.1 Pretraining Data and Objectives

> Prerequisites: 11.1–11.3 and train/validation/test isolation. Goal: connect pretraining objectives to provenance, quality, duplicates, document boundaries and mixtures.

## 1. More text is not automatically better supervision

Causal pretraining asks the model to predict what a source says, not whether the source is true, useful or safe. Duplicated spam and carefully edited explanations both produce valid next-token targets.

Data design therefore comes before optimization. Define permitted use, source provenance, language/domain coverage, personally identifying or sensitive content handling, quality criteria, duplicate handling and evaluation isolation. A toy keyword filter cannot establish all of these.

The lab uses fabricated records and explicit license flags. It does not inspect your personal notes, download a web corpus, or claim to make legal decisions automatically.

## 2. The training distribution is a design choice

Let $q(x)$ be the distribution of token sequences sampled by a training pipeline. The objective is

$$
L(\theta)=\mathbb E_{x\sim q}\left[-\log p_\theta(x)\right],
$$

This expression uses summed sequence NLL. If $S(x)$ is that sum and $M(x)$ the number of supervised targets, distinguish three objectives: sequence-sum expectation $\mathbb E_q[S]$, token-normalized corpus loss $\mathbb E_q[S]/\mathbb E_q[M]$, and equal-example mean $\mathbb E_q[S/M]$.

For a fixed data distribution, the first two differ only by a parameter-independent scale. The third generally gives short examples more weight per token. Moreover, with small randomly sampled variable-length batches, $\mathbb E[\sum S/\sum M]$ is not generally $\mathbb E[S]/\mathbb E[M]$: a random denominator changes the estimator. Fixed-token packing or a deliberately designed sampling/normalization scheme makes the intended weighting clearer. Our main LM and SFT examples each use equal target lengths, so this particular distinction does not alter their update direction.

Choosing a data mixture changes $q$, even if the model and optimizer are unchanged.

If one source is repeated ten times, it receives more optimization weight. That is not the same intervention as discovering ten independent sources. Repeated training tokens and unique data tokens should be reported separately.

“Self-supervised” means target labels are obtained from the sequence itself. It does not mean data curation is unnecessary or that training values are neutral.

## 3. Start with exact duplicates, then confront near duplicates

A cryptographic hash of a normalized document is useful for exact-match grouping. Our toy normalization lowercases and collapses whitespace, then computes SHA-256. Two documents with the same resulting text receive the same fingerprint.

The hash does not understand paraphrases. Normalization also changes the equality definition: lowercasing source code or collapsing layout can remove meaningful information. Choose it for the data type and preserve raw provenance.

For a simple near-duplicate illustration, let $A$ and $B$ be sets of word tokens. Jaccard overlap is

$$
J(A,B)=\frac{|A\cap B|}{|A\cup B|}.
$$

For “the red fox” versus “the red fox jumps”, the score is $3/4$. Word order is lost, so this is not a robust semantic or code duplicate detector. Shingles, MinHash and embeddings offer other tradeoffs; no single threshold works for every domain.

To avoid leakage, group duplicate or related source units before assigning splits. A mirror of a training document in validation is not independent evidence.

## 4. Contamination differs from ordinary repetition

A benchmark answer appearing in training can make an evaluation easier without improving generalization. Check known evaluation prompts, solutions and near duplicates against training candidates, while acknowledging that undetected paraphrases can remain.

The lab removes an exact normalized benchmark match from a toy corpus. This proves the filter handles that fixture, not that an actual corpus is contamination-free.

If you discover contamination after model selection, record it and rebuild the evaluation protocol. Do not quietly delete only inconvenient test examples after viewing results.

## 5. Packing saves padding, but boundaries need a policy

Several short documents can share a context window. Concatenating `doc_A EOS doc_B EOS` with a normal causal mask lets document B read A. EOS tells the model a boundary occurred; it does not mathematically block attention.

Two valid policies are:

- Stream training: permit cross-document conditioning and state this choice.
- Independent-document packing: use block-diagonal causal attention and exclude cross-document targets.

Let $s_i$ identify the document containing input position $i$. Under the second policy, query $i$ may read key $j$ when

$$
\mathrm{allowed}_{i,j}=\mathbf1[j\le i]\mathbf1[s_i=s_j].
$$

For globally shifted arrays, a transition from the end of one document to the first token of another must not be counted as an independent-document prediction. With per-document BOS/EOS, preserve within-document targets and mask transitions where adjacent segment IDs differ. Position-index reset or continuation is another explicit design choice.

Consider `[BOS,a,EOS, BOS,b,EOS]` with segment IDs `[0,0,0,1,1,1]`. Shifted inputs are `[BOS,a,EOS,BOS,b]` and targets are `[a,EOS,BOS,b,EOS]`. The valid target mask is `[1,1,0,1,1]`. The input at index 3 may read itself, but not indices 0–2. Masking only the cross-boundary loss still leaves the later document able to read the earlier one.

The extended experiment tests an actual attention read: alter values in document A and verify document B's outputs do not change under block-diagonal attention; remove the segment mask and verify that the same perturbation becomes visible. It does not claim that the shared TinyLM currently implements packed multi-document attention.

中文确认：把 EOS 塞进去不等于“文档已经隔离”。隔离必须体现在 attention 可见性和 target mask 两处。

## 6. Mixtures and temperature sampling

Suppose domain $i$ has size $n_i>0$. One illustrative sampling policy is

$$
w_i=\frac{n_i^\alpha}{\sum_j n_j^\alpha}.
$$

Here $\alpha$ is a mixture exponent, unrelated to decoding temperature. With sizes 900 and 100:

- $\alpha=1$: probabilities 0.9 and 0.1;
- $\alpha=0.5$: probabilities 0.75 and 0.25;
- $\alpha=0$: equal domain probabilities.

Smaller exponents upweight smaller domains relative to corpus-proportional sampling. Whether that improves the intended evaluation is empirical. Also define whether domain samples are documents, sequences, or tokens: unequal document lengths can change the resulting token mixture.

Quality filters can shift language and demographic coverage. Track per-source acceptance rates and evaluate relevant groups instead of assuming a global loss captures every effect.

## 7. Experiment and numerical check

The companion script exercises license flags, normalized exact duplicates, a known contamination fixture, Jaccard overlap, independent packed-document visibility and mixture weights.

```python
import torch
sizes = torch.tensor([900., 100.], dtype=torch.float64)
weights = sizes.sqrt() / sizes.sqrt().sum()
torch.testing.assert_close(weights, torch.tensor([.75,.25],dtype=torch.float64))
segments = torch.tensor([0,0,0,1,1,1])
positions = torch.arange(6)
allowed = (positions[:,None] >= positions[None,:]) & (segments[:,None] == segments[None,:])
assert not allowed[3:,:3].any()
print(weights, allowed.int())
```

Inspect the negative control: normal causal attention permits a later document to read an earlier document. This prevents an “isolation test” from passing simply because the fixture has no possible cross-document connections.

## 8. Objectives beyond ordinary next-token prediction

Masked prediction hides selected tokens; denoising reconstructs corrupted text; fill-in-the-middle changes ordering to train missing-span completion. Each objective changes which information is available and which positions are scored.

For example, a fill-in-the-middle serialization can place special PREFIX/SUFFIX/MIDDLE markers around `prefix, suffix, middle` in that order. The missing middle then conditions on both supplied sides, while attention remains causal in the **serialized order**. “Using a suffix” is not automatically future leakage: first specify which information the task deliberately supplies.

The core labs stay causal. Do not insert a bidirectional attention mask into a next-token setup without reconsidering target leakage. Objective choice, formatting, corpus and deployment task must be considered together.
