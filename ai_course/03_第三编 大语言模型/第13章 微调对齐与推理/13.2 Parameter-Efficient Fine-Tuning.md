## 1. Why freeze most of a model?

Full fine-tuning stores gradients and optimizer states for many parameters. If several tasks each need a separate full copy, deployment storage also grows.

Parameter-efficient fine-tuning trains a smaller set of task-specific parameters while using a frozen base. This restricts how the model can change. Reduced trainable parameter count is useful, but it is not equivalent to zero backward computation or zero activation memory.

Adapters insert small learned modules. Prefix/prompt tuning learns special representations. LoRA changes selected linear maps through a low-rank update. We study LoRA in detail because its algebra is transparent.

## 2. Factor the weight change, not the original weight

For input column vector $\mathbf x\in\mathbb R^{d_{\mathrm{in}}}$, a frozen base matrix $\mathbf W_0\in\mathbb R^{d_{\mathrm{out}}\times d_{\mathrm{in}}}$ gives $\mathbf W_0\mathbf x$.

Instead of training a full change $\Delta\mathbf W$, choose rank $r$ and factor

$$
\Delta\mathbf W=s\mathbf B\mathbf A,
\qquad
\mathbf A\in\mathbb R^{r\times d_{\mathrm{in}}},
\quad
\mathbf B\in\mathbb R^{d_{\mathrm{out}}\times r},
\quad s=\frac{\alpha}{r}.
$$

Here $\alpha$ is a scale hyperparameter, not a learning rate. The new output is

$$
\mathbf y=\mathbf W_0\mathbf x+s\mathbf B(\mathbf A\mathbf x).
$$

The bottleneck has width $r$, so the update rank is at most $r$. The original frozen weight need not be low rank.

For a numerical example, take $\mathbf W_0=\mathbf I_2$, $r=1$, $s=1$, $\mathbf A=\begin{bmatrix}1&2\end{bmatrix}$, $\mathbf B=\begin{bmatrix}3\\4\end{bmatrix}$ and $\mathbf x=\begin{bmatrix}1\\-1\end{bmatrix}$. The bottleneck is $\mathbf A\mathbf x=-1$, the update output is $[-3,-4]^{\mathsf T}$, and the final output is $[-2,-5]^{\mathsf T}$. The full update matrix is $\begin{bmatrix}3&6\\4&8\end{bmatrix}$; its second row is a multiple of its first, so its rank is 1.

For $d_{\mathrm{in}}=d_{\mathrm{out}}=4096$ and $r=8$, a full weight has 16,777,216 entries; the two factors have $8(4096+4096)=65,536$, or 1/256 as many. Biases and other adapted modules are outside this particular count.

## 3. Follow row-batch shapes

PyTorch batches store rows: $\mathbf X\in\mathbb R^{B\times d_{\mathrm{in}}}$. Then

$$
\mathbf H=\mathbf X\mathbf A^{\mathsf T}\in\mathbb R^{B\times r},
\qquad
\mathbf Y=\mathbf X\mathbf W_0^{\mathsf T}
+s\mathbf H\mathbf B^{\mathsf T}.
$$

Let upstream $\mathbf G=\partial L/\partial\mathbf Y$ have shape $(B,d_{\mathrm{out}})$. For one output coordinate,
$Y_{n,o}=\sum_i X_{n,i}W_{0,o,i}+s\sum_a H_{n,a}B_{o,a}$.
Changing $B_{o,a}$ changes every sample's output by $sH_{n,a}$, so
$\partial L/\partial B_{o,a}=s\sum_nG_{n,o}H_{n,a}$.
Stacking these coordinate sums gives

$$
\frac{\partial L}{\partial\mathbf B}=s\mathbf G^{\mathsf T}\mathbf H.
$$

The gradient into $\mathbf H$ is $s\mathbf G\mathbf B$. Applying the inner map gives

$$
\frac{\partial L}{\partial\mathbf A}
=s(\mathbf G\mathbf B)^{\mathsf T}\mathbf X.
$$

For $A_{a,i}$, first collect the gradient entering bottleneck coordinate $a$: $s\sum_oG_{n,o}B_{o,a}$. Multiply by $X_{n,i}$ and sum over samples. This explains both the transpose and the shared-batch sum in the matrix formula.

The input gradient must include both branches:

$$
\frac{\partial L}{\partial\mathbf X}
=\mathbf G\mathbf W_0+s\mathbf G\mathbf B\mathbf A.
$$

Freezing $\mathbf W_0$ means no parameter update to it; it does not remove its contribution to the input gradient needed by earlier trainable modules.

## 4. Why one factor starts at zero

Initialize $\mathbf A$ randomly and $\mathbf B=\mathbf0$. Then $\Delta\mathbf W=\mathbf0$, so the adapted model begins exactly at the base model.

From the gradient formulas, the first $\mathbf A$ gradient is zero, but $\mathbf B$ can receive a nonzero gradient because $\mathbf H=\mathbf X\mathbf A^{\mathsf T}$ is not zero. After $\mathbf B$ changes, both factors can learn.

If **both** factors start at zero, both gradients vanish for the isolated bilinear branch, trapping it at zero. This is not fixed merely by increasing the learning rate.

The lab checks these statements and then verifies both factor gradients and the input gradient against autograd with nonzero factors.

## 5. Merge equivalence and its conditions

For inference, define

$$
\mathbf W_{\mathrm{merged}}=\mathbf W_0+s\mathbf B\mathbf A.
$$

Then a single linear map matches the two-branch output in exact arithmetic. Finite precision can introduce small differences.

This assumes the simple branch used here: no active adapter dropout or input-dependent routing. If you already merged the update, do not also execute the adapter branch or you will add it twice. Quantized merging can require dequantization/requantization and is not necessarily bitwise equivalent.

## 6. What quantization changes

A simplified symmetric quantizer represents weight $w$ with an integer $q$ and scale $\Delta$:

$$
q=\operatorname{clip}\!\left(\operatorname{round}(w/\Delta),-7,7\right),
\qquad \widehat w=\Delta q.
$$

For unclipped values, rounding error is at most $\Delta/2$. For a fixed scale, values outside the representable interval saturate and can exceed that bound; a tensor of all zeros also needs a nonzero scale convention to avoid division by zero. Real quantization uses groups, metadata, special formats and hardware kernels. Storing 4-bit base weights does not imply all arithmetic, gradients and activations are 4-bit.

QLoRA combines a frozen quantized base with higher-precision trainable low-rank adapters and additional memory techniques. Our experiment checks only the simple quantization arithmetic; it does **not** implement QLoRA or measure GPU savings.

Memory includes base weights, trainable weights, gradients, optimizer states, activations and temporary buffers. Reducing one term may leave another dominant.

For a transparent FP32 Adam ledger, each trainable scalar can require 4 bytes for its weight, 4 for its gradient and 8 for two optimizer moments: 16 bytes before activations and buffers. A frozen FP32 scalar requires its 4-byte weight but no gradient/moments. Thus a simple estimate changes from $16P$ to $4P+16L$ bytes when $P$ base scalars are frozen and $L$ adapter scalars are trained. For $P=10^6,L=10^4$, those terms are 16 MB versus 4.16 MB in decimal units. Different precision/master-weight policies change the ledger. This is accounting, not a measured peak-memory reduction.

## 7. Experiment

The standalone LoRA lab adapts an $8\times6$ linear layer with rank 2, so 28 trainable entries replace 48 potential full-weight entries. This small example has modest savings; use the 4096-width calculation for scale intuition.

It trains against a known rank-2 target update, verifies loss reduction, frozen base weights, full manual gradients and merge equivalence. The target was deliberately chosen to fit the adapter's hypothesis class; this is not evidence that rank 2 suffices for arbitrary tasks.

```python
din = dout = 4096
rank = 8
full = din*dout
lora = rank*(din+dout)
assert lora == 65536 and full//lora == 256
print("full / LoRA entries:",full,lora)
```

### Code bridge: two factors and a frozen base

This self-contained example exposes exactly the two matrix multiplications and the first-step gradient asymmetry. `W0` still affects the forward/input derivative even though it is not trainable.

```python
import torch
torch.manual_seed(4)
W0 = torch.randn(3, 4, dtype=torch.float64)
A = torch.randn(2, 4, dtype=torch.float64, requires_grad=True)
B = torch.zeros(3, 2, dtype=torch.float64, requires_grad=True)
X = torch.randn(5, 4, dtype=torch.float64, requires_grad=True)
scale = 1.0
Y = X @ W0.T + scale * ((X @ A.T) @ B.T)
Y.square().mean().backward()
torch.testing.assert_close(A.grad, torch.zeros_like(A))
assert B.grad.norm() > 0 and X.grad.norm() > 0
assert W0.grad is None
```

The full lab wraps this branch in a module, trains its factors, checks finite differences and validates merge equivalence after training.
