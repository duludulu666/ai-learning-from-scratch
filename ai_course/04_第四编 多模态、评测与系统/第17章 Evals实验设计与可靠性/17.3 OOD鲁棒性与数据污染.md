## 1. A benchmark score is a conditional statement

A score describes performance under a particular dataset and protocol. Deployment can change cameras, writing styles, class proportions, annotation rules, languages, or user behavior. Generalization is not one binary property.

This lesson separates ordinary shift, deliberately bounded perturbations, and contamination. The lab uses local synthetic fixtures only; it does not attack external systems or modify a training corpus.

## 2. Name which part of the distribution changes

Let $p_{\mathrm{train}}(x,y)$ and $p_{\mathrm{test}}(x,y)$ denote joint input/label distributions.

- Covariate shift changes $p(x)$ while assuming $p(y\mid x)$ remains fixed.
- Label shift changes $p(y)$ while assuming $p(x\mid y)$ remains fixed.
- Concept shift changes the relationship $p(y\mid x)$.
- Open-set inputs include categories outside the known label space.

These are modeling assumptions, not labels that can always be uniquely inferred from a small dataset.

A simple shortcut example: during development, both shape and background predict the label. At deployment, background correlation reverses. A background-based classifier can have 100% ID accuracy and 0% accuracy under that constructed shift, while a shape-based rule succeeds in both. This demonstrates the ambiguity of ID evidence, not that we always know which feature is causal.

## 3. Importance weighting: useful only under assumptions

Under covariate shift with shared conditional labels,

$$
R_{\mathrm{test}}(f)
=\int \ell(f(x),y)\,p_{\mathrm{test}}(x)p(y\mid x)\,\mathrm{d}x\,\mathrm{d}y.
$$

Here $f$ is a predictor and $\ell$ its per-example loss. Multiply and divide by $p_{\mathrm{train}}(x)$ wherever it is positive:

$$
R_{\mathrm{test}}(f)
=\mathbb{E}_{(x,y)\sim p_{\mathrm{train}}}
\left[
\frac{p_{\mathrm{test}}(x)}{p_{\mathrm{train}}(x)}
\ell(f(x),y)
\right].
$$

The ratio reweights examples toward the target population. If test inputs occur where training probability is zero, this expression cannot estimate their contribution from training samples. Large ratios also create high-variance estimates. If $p(y\mid x)$ changes, the derivation's key assumption fails.

### A two-input risk calculation

Suppose inputs are only A and B. Source probabilities are $(.8,.2)$, target probabilities are $(.2,.8)$, and the fixed predictor has conditional losses $(0,1)$ under both domains. Source risk is .2 and target risk is .8.

The importance weights are $(.2/.8,.8/.2)=(.25,4)$. The source-weighted loss is $.8(.25)(0)+.2(4)(1)=.8$, matching target risk. This works because the conditional loss is unchanged and source support covers both inputs.

The lab checks this exact identity. It also keeps a cautionary normalization collision: the simple word-token normalizer maps both “C++” and “C” to “c”. A duplicate candidate flag should lead to source-aware review, not automatic destructive removal.

## 4. Robustness needs a threat model

To test bounded sensitivity, define allowed perturbations, the attacker/tester's information, and the success condition. For a differentiable classifier and label $y$, a first-order loss expansion gives

$$
\ell(x+\boldsymbol{\delta},y)
\approx \ell(x,y)+
\nabla_x\ell(x,y)^{\mathsf T}\boldsymbol{\delta}.
$$

Under coordinate-wise constraint $\lVert\boldsymbol{\delta}\rVert_\infty\leq\epsilon$, each coordinate maximizes its linear contribution by choosing the gradient's sign:

$$
\boldsymbol{\delta}=\epsilon\operatorname{sign}(\nabla_x\ell).
$$

This is the one-step FGSM direction. It increases the linear approximation, not necessarily the exact nonlinear loss for every step size. If inputs have a valid range, project back into that range; the toy scalar fixture has no additional box constraint.

For scalar logit $10x$, positive target, and $x=.1$, the loss gradient with respect to $x$ is negative. With $\epsilon=.2$, the perturbed input is $-.1$, crossing the decision boundary. This is a constructed local sensitivity example, not a practical attack recipe or a certification test.

Robustness to one perturbation norm does not imply robustness to semantic changes, sensor failures, or prompt injection. A finite set of tests cannot certify all possible inputs.

## 5. Contamination can survive an exact-string check

If a test item, near-duplicate, answer key, or derived variant appears in training/development data, the measured task may partly be memorization.

Exact hashing detects identical bytes. Normalization can catch case, punctuation, and spacing differences. Near-duplicate detection can use token shingles or embeddings followed by review. None proves absence of semantic overlap.

The companion shows that “The small cat sits.” and “ THE small CAT sits! ” differ as raw strings but match after a stated normalization. Such normalization can also merge legitimately distinct strings; preserve originals and audit the rule.

For videos, group identity may matter more than exact frame duplication. Two nonidentical frames from the same scene can leak background and event identity. Split by original source/session before extracting examples when that matches the deployment question.

## 6. What to record in a data audit

Record source and license, collection date, group identity, transformation lineage, labeling procedure, train/validation/test assignment, known overlaps, and limitations. Version both data and evaluation code.

A clean benchmark score does not reveal the contents of a closed model's pretraining corpus. If overlap cannot be inspected, state uncertainty and use additional fresh, private-with-consent, temporal, or procedurally generated tests as appropriate. Synthetic tests also have blind spots and can be solved by generator-specific shortcuts.

Do not put secret evaluation answers into prompts used during development. Keep “regression suite built from past failures” separate from “untouched final holdout”; both are useful, but they answer different questions.

### Standalone importance-weighting check

```python
import torch
source = torch.tensor([.8, .2], dtype=torch.float64)
target = torch.tensor([.2, .8], dtype=torch.float64)
conditional_loss = torch.tensor([0., 1.], dtype=torch.float64)
weights = target / source
weighted = (source * weights * conditional_loss).sum()
torch.testing.assert_close(weighted, (target * conditional_loss).sum())
```

This finite enumeration verifies the population identity exactly for the declared assumptions; it does not estimate unknown density ratios from real data.
