## 1. A video is not just a larger batch of images

Two clips can contain exactly the same frames in opposite orders. “An object is rising” and “an object is falling” are different events, although the average frame feature can be identical.

Treating time as an independent-example batch throughout the predictor discards relationships between frames. Temporarily merging $B,T$ to apply a frame encoder is fine if you restore the time axis before temporal modeling. Treating time as sequence preserves the possibility of modeling order, but only if timestamps, positions, and masks are correct.

This chapter uses synthetic sequences and generic moving-object examples. It neither reads nor changes your separate traffic research project.

## 2. Establish the axes and sampling rule

A video batch may have shape $(B,T,C,H,W)$: $T$ sampled frames per example. A per-frame encoder turns it into $\mathbf{Z}\in\mathbb{R}^{B\times T\times N\times D}$, with $N$ spatial tokens and width $D$.

If the original stream has frame rate $f$ frames/second and we keep every $s$-th frame, neighboring retained frames are $s/f$ seconds apart. With $T$ retained frames, the elapsed interval between first and last is

$$
\Delta t=\frac{(T-1)s}{f}.
$$

For $f=30,s=3,T=11$, the interval is one second. Eleven frames at this sampling rate do not span eleven seconds. Uneven sampling requires actual timestamps rather than assuming constant spacing.

Sampling can miss brief events. If a light flashes entirely between sampled frames, no downstream model can reconstruct that event with certainty from the selected observations alone.

## 3. What pooling loses: a hand example

Consider scalar frame features $(0,1,2,3)$ and $(3,2,1,0)$. Both means are 1.5. A classifier that sees only this mean must give the same output for both.

An endpoint difference keeps some directional information:

$$
d=z_{T-1}-z_0.
$$

It gives $+3$ and $-3$, respectively. This baseline is not a universal motion model: $(0,3,0)$ has endpoint difference zero despite substantial movement.

A temporal Transformer can use all frame states. Add a temporal position or timestamp embedding $\mathbf{e}_t$ to each feature before attention. If spatial tokens are retained, represent both frame time and spatial position; one flat index does not automatically encode their intended geometry.

## 4. Joint versus factorized attention

For one example, full attention over all $TN$ tokens forms $(TN)\times(TN)$ scores, requiring order $T^2N^2$ pair comparisons per head.

A factorized block can first attend over $N$ spatial tokens within each of $T$ frames, costing order $TN^2$, then over $T$ times at each of $N$ spatial indices, costing order $NT^2$:

$$
\text{pair count}\ \propto\ TN^2+NT^2.
$$

This is a different architecture, not an algebraically exact rearrangement of joint attention. Objects can move between patch indices; temporal attention along a fixed grid must learn around that fact. Pooling each frame to one vector is cheaper still, but may lose small-object details.

Example: $T=8,N=16$. Joint attention uses $128^2=16{,}384$ pairs per head. The factorized count is $8(16^2)+16(8^2)=3{,}072$, excluding projections and FFNs. Reduced pair count does not directly specify wall-clock speed.

## 5. Offline recognition versus online detection

Offline recognition can use the whole clip. Online detection at time $t$ may use only frames whose timestamps are no later than $t$. Define allowed temporal attention by

$$
M_{ij}=
\begin{cases}
0,&j\leq i,\\
-\infty,&j>i.
\end{cases}
$$

This mask blocks future keys for query time $i$. But the mask alone is not enough: centered smoothing, preprocessing using a whole clip, or frame features computed from future frames can leak information earlier in the pipeline. A future outcome may legitimately be a forecasting target; leakage occurs when future-only information enters the predictor or the evaluation protocol gives it unavailable evidence, not simply because a label describes the future.

中文确认：在线任务要求的是整条计算链没有偷看未来，不只是 attention 矩阵看起来是下三角。

For a genuinely online score, changing frames after time $t$ should not change predictions at or before $t$. This is a useful executable invariance test.

```python
import torch
from torch import nn
torch.manual_seed(161)
attn = nn.MultiheadAttention(4, 2, dropout=0, batch_first=True).eval()
x = torch.randn(1, 6, 4)
changed = x.clone()
changed[:, 4:] += 30
blocked = torch.ones(6, 6, dtype=torch.bool).triu(1)
a = attn(x, x, x, attn_mask=blocked, need_weights=False)[0]
b = attn(changed, changed, changed, attn_mask=blocked, need_weights=False)[0]
torch.testing.assert_close(a[:, :4], b[:, :4])
```

This isolates causal attention. It is not an end-to-end certification of a video preprocessing system.

## 6. Detection quality includes time and false alarms

Suppose an event starts at index $t_0$ and the first valid alarm occurs at $\widehat t\geq t_0$. Detection delay is $(\widehat t-t_0)s/f$ seconds. Missed events have no finite observed detection time and must be counted separately, not silently removed from an average.

A threshold on every frame can trigger many repeated alerts. An event-level protocol must define matching tolerance, minimum duration, cooldown, overlapping events, and which alarms count as false positives. Frame accuracy alone often favors predicting “normal” all the time.

The laboratory includes a causal exponential moving average:

$$
h_t=\alpha h_{t-1}+(1-\alpha)x_t,
\qquad 0\leq\alpha<1.
$$

Here $x_t$ is a scalar observation, $h_t$ is a smoothed score, and $\alpha$ controls history. Starting at zero with $\alpha=0.5$, an onset from 0 to 1 gives states 0.5 then 0.75. A fixed threshold 0.7 therefore introduces one sample of delay. Smoothing reduces fluctuations but can delay detection.

### An event-level scoring example

For a simple declared protocol, ground-truth events occupy disjoint inclusive sample intervals $[4,6]$ and $[10,12]$. Process alarms chronologically; the first alarm within an unmatched event is a TP, and each remaining alarm is an FP. No early tolerance or duplicate suppression is used.

For alarms $(5,6,9)$, alarm 5 matches the first event, alarm 6 is a duplicate FP, and alarm 9 is an FP. The second event is missed. Thus TP=1, FP=2, FN=1, event precision=$1/3$, event recall=$1/2$, and the single matched delay is one sample.

This matching algorithm uses ground truth **only for scoring**, not prediction. Another application might suppress duplicates or permit early warnings; declare that rule before comparison. If false alarms/hour uses only normal time, explicitly exclude event duration from the denominator. Dividing by total monitoring time defines a different rate.
