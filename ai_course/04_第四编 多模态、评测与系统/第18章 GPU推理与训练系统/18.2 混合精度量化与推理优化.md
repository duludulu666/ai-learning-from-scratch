## 1. Smaller numbers save memory, but change numerical behavior

Precision changes the representation of numbers, while algorithmic optimization changes how computation is organized. They often interact, but “uses fewer bits” does not automatically mean “faster and equally accurate.”

FP16 and BF16 are floating-point formats; INT8 quantization maps real values to a finite integer grid using scales. Weight-only quantization, activation quantization, and KV-cache quantization affect different tensors. State exactly which are changed.

## 2. Range and precision are separate properties

FP16 has 5 exponent bits and 10 explicit fraction bits. BF16 has 8 exponent bits and 7 explicit fraction bits. FP32 has 8 exponent bits and 23 explicit fraction bits.

BF16 therefore has a range similar to FP32 but coarser precision near a number; FP16 has finer fraction resolution than BF16 but a much smaller range. FP16's largest finite value is 65,504, so converting $10^5$ overflows, whereas BF16 can represent a nearby finite value.

Mixed precision chooses suitable dtypes for different operations and often uses higher-precision accumulation or sensitive reductions. Exact dispatch depends on backend and hardware. BF16 generally avoids FP16-style loss scaling needs for range, but still has rounding error and does not make unstable algorithms stable.

## 3. Derive loss scaling without mysticism

Small gradients may underflow in FP16. Multiply scalar loss $L$ by a positive scale $S$ before backward:

$$
\nabla_\theta(SL)=S\nabla_\theta L.
$$

Then divide stored gradients by $S$ before the optimizer uses them. In exact arithmetic the update is unchanged; in finite precision the larger intermediate values can avoid underflow.

A dynamic scaler detects nonfinite gradients, skips invalid updates, and adjusts the scale. Unscale before gradient-norm clipping, otherwise the clipping threshold applies to an artificially enlarged gradient. Loss scaling cannot rescue an already overflowing forward activation.

The companion verifies only the exact algebra with FP32 autograd. It does **not** run GPU autocast, dynamic scaling, or a speed benchmark.

## 4. Quantization starts from a grid

For one weight row $\mathbf{w}$, choose symmetric INT8 levels $-127,\ldots,127$ and scale

$$
s=\frac{\max_j|w_j|}{127}.
$$

For an all-zero row, choose any positive scale, such as 1. Quantize and reconstruct:

$$
q_j=\operatorname{clip}\!\left(
\operatorname{round}(w_j/s),-127,127
\right),
\qquad
\widehat w_j=sq_j.
$$

The zero point is zero in this symmetric scheme. Asymmetric quantization adds a zero-point offset and has different bookkeeping.

If no value saturates and rounding is to the nearest grid point, the scalar error satisfies $|\widehat w_j-w_j|\leq s/2$. An outlier enlarges $s$ and makes the grid coarse for other values. Per-channel/row scales can reduce this compared with one scale for the entire matrix.

For $\mathbf{w}=(0,1,-2)$, $s=2/127$. Quantized values are approximately $(0,64,-127)$ under round-to-even, and reconstruction is $(0,128/127,-2)$. The middle error is about .00787.

## 5. From weight error to output error

For one output $y=\sum_jx_jw_j$, reconstructed output is $\widehat y=\sum_jx_j\widehat w_j$. Subtract and use the triangle inequality:

$$
|\widehat y-y|
=\left|\sum_jx_j(\widehat w_j-w_j)\right|
\leq\sum_j|x_j|\,|\widehat w_j-w_j|
\leq\frac{s}{2}\sum_j|x_j|.
$$

This local bound assumes the row's unsaturated nearest-grid error bound. It can be loose, and a deep network can amplify or alter errors through nonlinearities. Validate task quality, not just weight MSE.

```python
import torch
w = torch.tensor([[0., 1., -2.], [0., 0., 0.]])
peak = w.abs().amax(1, keepdim=True)
scale = torch.where(peak > 0, peak / 127, torch.ones_like(peak))
q = torch.round(w / scale).clamp(-127, 127).to(torch.int8)
restored = q.float() * scale
assert ((restored - w).abs() <= scale / 2 + 1e-6).all()
```

## 6. KV-cache memory: count every axis

For $L$ decoder layers, batch $B$, cached length $T$, $h_{\mathrm{kv}}$ key/value heads, head width $d_h$, and $s$ bytes per scalar, both K and V require

$$
M_{\mathrm{KV}}=2LBT h_{\mathrm{kv}}d_hs.
$$

The factor 2 is for keys and values, not training gradients. With $L=12,B=2,T=128,h_{\mathrm{kv}}=4,d_h=16,s=2$, memory is 786,432 bytes, or .75 MiB, excluding allocator overhead and temporary attention tensors.

Grouped-query attention can have fewer KV heads than query heads. Weight quantization leaves this cache unchanged unless the cache itself is separately quantized. Reusing cross-attention visual K/V is a related but distinct cache with its own dimensions.

## 7. Optimization mechanisms and their verification

- Fused attention reduces intermediate memory traffic; check mask semantics and numerical agreement.
- Continuous batching improves serving utilization by admitting/removing sequences dynamically; queueing and fairness still matter.
- Paged cache management reduces allocation waste and supports dynamic lengths; it does not erase the information stored per token.
- Speculative decoding proposes several tokens with a cheaper draft and verifies them with the target. Exact sampling preservation requires the correct acceptance/rejection procedure; naive acceptance changes the distribution.
- Prefix caching reuses identical compatible context states; cache identity must include model, tokenization, position, and relevant configuration.

These are conceptual extensions here, not implemented serving features. Part II already provides a cached/full-prefix equivalence experiment. Before adopting a system optimization, repeat correctness checks and measure end-to-end quality/latency under a fixed workload.

### Why speculative acceptance needs a correction distribution

Study one token at a fixed prefix. Let $p(v)$ be the target distribution and $q(v)$ the draft distribution over token $v$. Draw from $q$, then accept the proposal with probability

$$
a(v)=\min\left(1,\frac{p(v)}{q(v)}\right)
$$

for a proposed token with $q(v)>0$. Accepted probability mass is $q(v)a(v)=\min(q(v),p(v))$. This is not yet all of $p$: some target mass is missing wherever $p(v)>q(v)$.

The rejection probability is
$R=1-\sum_v\min(p(v),q(v))=\sum_v[p(v)-q(v)]_+$,
where $[x]_+=\max(x,0)$. If rejected and $R>0$, sample from the residual distribution

$$
r(v)=\frac{[p(v)-q(v)]_+}{R}.
$$

The final mass is $\min(p(v),q(v))+Rr(v)=p(v)$. If $R=0$, no residual draw is needed. Tokens with zero draft probability can still receive mass through the residual.

For $p=(.6,.3,.1)$ and $q=(.2,.3,.5)$, accepted masses are $(.2,.3,.1)$; rejection probability is .4 and residual always chooses the first token. Their sum is exactly $p$.

The lab verifies this **one-token distribution identity**. It does not implement a multi-token draft/verify engine or measure acceleration. Acceptance rates, verification cost, cache handling, and batching determine whether a full implementation is faster.
