## 1. The question: how can a Transformer read an image?

A language model receives an ordered list of token vectors. An image arrives as a grid of pixel values. We need a transformation from the grid to a list, but flattening the entire image into one vector would give attention only one item to compare. Giving attention every individual pixel is expensive and provides very small local units.

A Vision Transformer (ViT) uses **patches**: small, non-overlapping image regions. Each patch becomes one token. Attention then communicates between regions; an MLP transforms each region's features. This reuses the Transformer mechanism from Part II, not its text tokenizer.

Prerequisites: convolution in 05.1, attention in 08.1, position information in 09.1. Our laboratory trains a tiny classifier from scratch; it does not load a pretrained vision encoder.

## 2. First count the patches, then define the projection

Let an image batch be $\mathbf{X}\in\mathbb{R}^{B\times C\times H\times W}$. Here $B$ is batch size, $C$ is channel count, and $H,W$ are image height and width. A square patch has side $P$. Assume $H,W$ are divisible by $P$ and use no padding.

There are $H/P$ patch rows and $W/P$ patch columns. Therefore the sequence length is

$$
N=\frac{H}{P}\frac{W}{P}.
$$

Each patch contains $CP^2$ numbers. Define $F=CP^2$, and flatten the patches into $\mathbf{U}\in\mathbb{R}^{B\times N\times F}$. Flattening chooses an ordering; it does not learn anything.

To get token width $D$, use a learned weight $\mathbf{E}\in\mathbb{R}^{D\times F}$ and bias $\mathbf{b}\in\mathbb{R}^{D}$. For patch $i$ of example $b$,

$$
\mathbf{z}_{b,i}=\mathbf{E}\mathbf{u}_{b,i}+\mathbf{b}.
$$

The same $\mathbf{E}$ is used at every patch. This is precisely a convolution with kernel size $P$, stride $P$, and $D$ output channels, followed by flattening the spatial axes. It is not $N$ different linear layers.

中文确认：一个 patch 变成一个 token；token 的长度是模型宽度 $D$，不是 patch 的数量 $N$。PyTorch 存储的线性权重仍然是“输出维度在前”。

## 3. A hand-worked image

Take one grayscale $4\times4$ image:

$$
\mathbf{X}=
\begin{bmatrix}
1&2&3&4\cr
5&6&7&8\cr
9&10&11&12\cr
13&14&15&16
\end{bmatrix}.
$$

For $P=2$, the first flattened patch is $(1,2,5,6)^{\mathsf T}$ and the second is $(3,4,7,8)^{\mathsf T}$. There are $N=4$ patches, each with $F=4$ entries.

Choose $D=2$, zero bias, and

$$
\mathbf{E}=
\begin{bmatrix}
1&0&0&1\cr
0&1&1&0
\end{bmatrix}.
$$

The first token is $(7,7)^{\mathsf T}$; the second is $(11,11)^{\mathsf T}$. This particular projection loses information: different patches can have the same two diagonal sums. A learned projection is also a bottleneck when $D<F$; training decides which distinctions to retain.

## 4. Why position is still necessary

Self-attention without positional information is permutation equivariant. If you permute patch tokens, the output tokens are permuted in the same way. Mean pooling then removes the permutation entirely. Thus a position-free encoder with mean pooling treats an image as a bag of patches.

Add a position table $\mathbf{P}_{\mathrm{pos}}\in\mathbb{R}^{1\times N\times D}$:

$$
\mathbf{H}^{(0)}=\mathbf{Z}+\mathbf{P}_{\mathrm{pos}}.
$$

The batch dimension broadcasts. The symbol $\mathbf{P}_{\mathrm{pos}}$ is distinct from patch side $P$. A pre-LN encoder block then applies

$$
\begin{aligned}
\mathbf{U}^{(\ell)}
&=\mathbf{H}^{(\ell)}+
\mathrm{MHA}\!\left(\mathrm{LN}(\mathbf{H}^{(\ell)})\right),\cr
\mathbf{H}^{(\ell+1)}
&=\mathbf{U}^{(\ell)}+
\mathrm{FFN}\!\left(\mathrm{LN}(\mathbf{U}^{(\ell)})\right).
\end{aligned}
$$

Here $\ell$ indexes layers; MHA is multi-head self-attention and FFN is the per-token feed-forward network already derived in Part II. These equations add communication and nonlinear processing; patch projection alone is not a complete ViT.

To classify, mean-pool the final normalized tokens and apply a linear classification head. Another design prepends a learned class token and uses its final representation. These are alternatives, not two mandatory operations.

### The actual model: a shape and parameter ledger

The companion's default PyTorch encoder uses **ReLU**, not GELU, inside its FFN. The broad ViT mechanism does not require one specific activation; this distinction matters when reproducing a particular paper. Here $B$ is arbitrary and all input images are $(1,8,8)$.

| Stage | Output shape | Trainable parameters |
|---|---|---:|
| Patch Conv2d, $P=2,D=16$ | $(B,16,4,4)$ | $16(1\cdot2^2+1)=80$ |
| Flatten/transpose; add positions | $(B,16,16)$ | $16\cdot16=256$ |
| Two-head self-attention | $(B,16,16)$ | Q/K/V: $3(16^2+16)=816$; output: $16^2+16=272$ |
| FFN, $16\to32\to16$ | $(B,16,16)$ | $(16\cdot32+32)+(32\cdot16+16)=1,072$ |
| Two block LayerNorms | $(B,16,16)$ | $2(16+16)=64$ |
| Final LayerNorm | $(B,16,16)$ | $16+16=32$ |
| Mean and two-class head | $(B,2)$ | $16\cdot2+2=34$ |
| Total | — | **2,626** |

Attention mixes tokens; the FFN and normalization keep token count unchanged. Parameters do not multiply by batch size or token count, except the learned position table's own length.

The extended lab checks both forward values and input/weight/bias gradients for RGB patch projection. It also tests position-free mean-pooling invariance and rejects a wrong image width rather than allowing convolution to silently drop its last column.

## 5. Resolution, sequence length, and cost

For RGB $224\times224$ images and $P=16$, $F=768$ and $N=196$. At $448\times448$ with the same patch size, $N=784$: four times as many tokens and sixteen times as many pairwise attention scores.

The score matrix for $h$ heads has shape $(B,h,N,N)$. Its storage is quadratic in $N$ if materialized; fused attention can avoid storing the full matrix but does not remove dense attention's quadratic arithmetic.

A learned position table for 196 tokens cannot simply be added to 784 tokens. Interpolating the two-dimensional grid is a common adaptation, but changing resolution also changes data and compute; interpolation is not proof of preserved accuracy. Our minimal model has a fixed $8\times8$ input contract.

## 6. Runnable patch-equivalence check

```python
import torch
from torch import nn
import torch.nn.functional as F

torch.manual_seed(151)
x = torch.randn(2, 1, 8, 8)
projection = nn.Conv2d(1, 6, kernel_size=2, stride=2)
patches = F.unfold(x, kernel_size=2, stride=2).transpose(1, 2)
a = F.linear(patches, projection.weight.flatten(1), projection.bias)
b = projection(x).flatten(2).transpose(1, 2)
torch.testing.assert_close(a, b)
assert a.shape == (2, 16, 6)
```

`unfold` creates patch columns, so the transpose changes $(B,F,N)$ into $(B,N,F)$. Convolution produces $(B,D,4,4)$; flattening and transposing produces the same token layout. Matching both values and shapes is stronger evidence than matching shapes alone.

## 8. Mistakes and counterexamples

- Flattening $(B,C,H,W)$ directly into $(B,HW,C)$ by a reshape can mix channel ordering. Use an explicit permutation or a tested patch operation.
- Reducing patch size increases sequence length and attention cost; “more detail” is not free.
- A mean-pooled, position-free model cannot distinguish every spatial arrangement.
- Calling random features “pretrained representations” confuses architecture with learned knowledge.
- Freezing a random encoder is not equivalent to freezing a useful pretrained encoder.
